# FE-033 人工结构修改：范围确认与共同约束

日期：2026-09-24。状态：设计待范围确认；不是 FE-033 的实现或验收。

当前实现可按业务解析修订读取 Doclib 的历史原生父子块树，包含块类型、标题级别、层级路径、顶层块定位器、可用 bbox 与短文本预览。它是**机器解析、未人工确认**的只读结果。子块继承顶层块定位器，不能把其路径冒充精确的独立定位器。现有字段人工决定和冻结证据存储不包含结构修订；前端目前只展示结构树。

共同设计约束：

1. 不原地修改 MinerU/Doclib 的历史 Middle JSON、解析修订、原文文件或已冻结证据。业务侧的人工结构决定应单独持久化、可追溯到业务文档 ID、解析修订 ID、页码、原生节点路径/顶层定位器与原始机器值；后续操作追加记录而非改写历史决定。
2. 写入时重新核验业务修订与节点身份，拒绝跨文档、跨修订、页码/路径/定位器不匹配；用户提供的值和原因限制长度，显示时只作文本处理。不能凭短预览推断模型没有提供的表格单元格、图片内部层级或几何坐标。
3. 结构决定属于内容复核状态，不是用户身份、角色或审批权限。开放 Web 与自有 Skill 必须走同一业务 API；审计只记 `web/api/skill` 来源，不伪称可追踪个人。
4. 原生机器结构与人工决定必须在 API、Web、导出中明确区分；已有字段决定、确认成果、证据快照不会因结构决定自动重写。若要生成“已确认结构成果”，需定义独立的版本化产物及确认规则。
5. 新系统零历史兼容。业务库若扩展 schema，开发原型可用新空库初始化；生产发布后不能随意丢弃已上线数据，须有明确版本与备份/升级流程。

待用户确认的范围：

| 方案 | 首版可编辑 | 主要后果 |
| --- | --- | --- |
| A（建议） | 顶层块类型、标题级别；保存原值、新值、依据与原因 | 可做修订绑定的业务叠加层，不改变文本、节点位置、定位器和父子关系；易于核验与回滚。 |
| B | 还包括块文本、增删/移动节点、父子关系 | 需要新派生结构版本、稳定节点身份、文本与证据重新锚定、冲突检测和导出契约；不能作为 A 的几个表单字段扩展。 |

无论选择哪一种，FE-033 需经过后端不变量测试、业务 API 测试、浏览器写入/重读/跨修订隔离测试，以及最终真实样本复核；不能仅凭一个“编辑”按钮标完成。待范围确认后再写具体 schema/API 和代码。
