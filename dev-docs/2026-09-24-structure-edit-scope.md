# FE-033 人工结构修改：范围确认与共同约束

日期：2026-09-24，2026-09-29 更新。状态：用户已选 **B**；以下为实施契约，FE-033 尚未实现或验收。

当前实现可按业务解析修订读取 Doclib 的历史原生父子块树，包含块类型、标题级别、层级路径、顶层块定位器、可用 bbox 与短文本预览。它是**机器解析、未人工确认**的只读结果。子块继承顶层块定位器，不能把其路径冒充精确的独立定位器。现有字段人工决定和冻结证据存储不包含结构修订；前端目前只展示结构树。

共同设计约束：

1. 不原地修改 MinerU/Doclib 的历史 Middle JSON、解析修订、原文文件或已冻结证据。业务侧的人工结构决定应单独持久化、可追溯到业务文档 ID、解析修订 ID、页码、原生节点路径/顶层定位器与原始机器值；后续操作追加记录而非改写历史决定。
2. 写入时重新核验业务修订与节点身份，拒绝跨文档、跨修订、页码/路径/定位器不匹配；用户提供的值和原因限制长度，显示时只作文本处理。不能凭短预览推断模型没有提供的表格单元格、图片内部层级或几何坐标。
3. 结构决定属于内容复核状态，不是用户身份、角色或审批权限。开放 Web 与自有 Skill 必须走同一业务 API；审计只记 `web/api/skill` 来源，不伪称可追踪个人。
4. 原生机器结构与人工决定必须在 API、Web、导出中明确区分；已有字段决定、确认成果、证据快照不会因结构决定自动重写。若要生成“已确认结构成果”，需定义独立的版本化产物及确认规则。
5. 新系统零历史兼容。业务库若扩展 schema，开发原型可用新空库初始化；生产发布后不能随意丢弃已上线数据，须有明确版本与备份/升级流程。

## B 的版本与来源契约

1. 原生结构接口继续只读，原生节点的 `path` 只在**指定解析修订的指定页**内有意义。业务侧首次编辑时从该页完整历史解析结果创建派生结构 v1；每次成功操作追加 v2、v3……，保留旧版本和操作记录。页面版本采用乐观并发条件（例如 `If-Match`），陈旧版本返回冲突，不自动覆盖。新解析修订有自己的 v1，不承袭旧修订的人工修改。
2. 派生节点使用业务稳定 `node_id`，并记录 `origin_revision_id`、`origin_page_no`、原生 `path`、原生顶层 `locator`、原始机器类型/文字摘要。拆分产生新节点 ID 并保留来源关系；合并保留全部来源节点 ID，不能伪称为单一原文块。完全人工新增的节点无原生路径、bbox 或精确定位器。重排和改父子关系不改变来源坐标。
3. 目前 Doclib `read_parse_structure` 只提供最多 200 字的 `preview`。**不得**把预览当完整文字保存或允许据此覆盖长正文。先扩展一个按历史解析批次/页/路径读取完整可编辑文字的只读契约，再允许文字修改、拆分或合并；不适合文本编辑的表格/图片/公式节点仅能调整外层类型/层级或移动，不伪造其内部内容。全文响应与写入均设单节点/单页上限。
4. 写入只能提交有限操作：改类型/标题级别、改完整文字、按合法字符边界拆分文本节点、合并相邻同级文本节点、同页移动/重排（禁止环）、增删人工节点。服务端重读当前版本、检验节点存在与归属、页码/修订、树深/节点数、类型与文本限制；客户端不能直接上传任意完整树来冒充机器原值。每个操作含来源 `web/api/skill` 与原因，审计不记录不存在的用户身份。
5. 原生解析、冻结证据、字段决定、已确认成果保持不变。派生节点的原生 locator 只是**来源锚点**；文字被人工改过、拆分/合并或移动后，它不能自动成为准确原文引用。引用原文须重新按历史修订冻结证据。结构导出单独标记 `human_edited_structure` 与版本 ID，不静默替换历史 Markdown 或已确认成果。Web 与自有 Skill 均调用同一业务 API，并明确展示原生/人工结构状态。

实施顺序：先补 Doclib 完整文字读取及契约测试，再做业务页版本与操作不变量/API，随后 Web 操作与自有 Skill 读取/编辑入口，最后用本地公开样本做写入—重读—冲突—跨修订隔离测试。目标麒麟与 GPU/OCR/真实人工标注验收仍另行留门禁。

第一关口已实现只读历史节点全文的 Doclib 与业务 API 契约，验证及明确限制见[证据记录](evidence/2026-09-29-structure-node-text.md)。这不是 FE-033 的人工结构编辑完成声明；派生结构版本、写入操作、Web/Skill 入口仍待实现。

第二关口已实现业务侧 schema 19 的 `structure_versions` 追加式页版本与有限操作 API，验证见[派生结构证据](evidence/2026-09-29-structure-versioned-operations.md)。`GET /api/business/revisions/{revision_id}/structure/derived?page_no=N[&version=V]` 的 v0 是未写入的原生结构视图；首次写入得 v1，后续每次成功操作追加 v2、v3 等。`POST /api/business/revisions/{revision_id}/structure/operations` 必须提交 `page_no`、`expected_version`、`operation`、`source` 和 `reason`；来源限 `web/skill/api`，不代表个人身份。旧版本写入返回 409，不自动合并。可带 `Idempotency-Key` 并用 `GET /api/business/structure-requests/{key}` 查原响应；同键同意图重放不增加版本，同键异意图冲突。客户端在响应未知时不得换新键自动重试。

原生节点 ID 由修订/页/原生路径稳定生成；拆分、合并、人工插入生成新 ID。每个节点保留来源路径、顶层定位器和机器原值预览；`text_override` 是人工完整文字，不是原始解析文字。`content_changed=true` 或多个来源时，原生定位器仅是来源锚点。合并仅允许相邻同级且类型/标题级别相同的纯文字叶节点；移动仅限本页，`index` 按移除旧位置后的目标子列表计算，禁止移动到自身后代。拆分偏移按 Python Unicode 字符位置计，必须两侧均有非空文字。单页最多 500 顶层/2000 总节点、深度 16、派生文字总计 50 万字符；单节点文字上限 10 万字符。人工新增限正文/文档标题/段落标题。页版本 JSON 与操作 JSON 都有 SHA-256 检查，发现单侧损坏时拒绝读取；这不是防数据库管理员同时篡改内容和哈希的签名。旧字段证据和确认成果不会随结构版本变化。

Web 与自有 Skill 的编辑/读取入口、人工结构导出格式及浏览器写入回读仍是下一关口；不能因后端 API 能写而将 FE-033 标完成。

2026-09-29 的[报纸 PDF 冒烟](evidence/2026-09-29-downloads-sample-smoke.md)给出一个直观用例：一大段正文被机器标成 `paragraph_title`。首版应能把该块改为正文；若另有识别错字、多栏文章错序或错归属，则可用 B 的文字、拆分/合并和树结构操作修正。每种修正都只形成业务派生版本，不修改 MinerU 原始解析文件，也不自动改写已有引用和成果。
