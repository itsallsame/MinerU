# MinerU 4 业务文档平台架构设计

状态：设计基线，待原型验证后固化实现细节。仓库 `itsallsame/MinerU` 的 `master` 是唯一开发主线；不保留旧 3.4/V1 API、数据或代码兼容。

## 目标

基于 MinerU 4.0.6 源码构建一套离线业务文档平台。MinerU 提供解析、档位、文档库、缓存、搜索、续读和定位器；本产品提供业务模板、字段提取、质量检查、原文证据、人工复核、确认、成果、前端和自有 Skill。Mac 仅开发测试，生产是完全物理隔离的银河麒麟 x86_64 + NVIDIA。

## 核心概念与数据所有权

| 概念 | 所有者 | 关键约束 |
| --- | --- | --- |
| 原文件与 MinerU 文档身份 | Doclib | 文档内容与索引唯一来源；业务系统不复制全文索引 |
| 解析修订 | MinerU + 业务引用 | 保存实际 tier、生产者版本、输入哈希与可复查定位器；重新解析不覆盖已确认依据 |
| 业务文档/任务 | 业务模块 | 关联 Doclib 文档身份；独立的可恢复业务状态，不使用 V1 临时 job ID 当业务 ID |
| 模板版本和候选字段 | 业务模块 | 公文、论文、研究报告、报纸和自定义类型；字段需绑定原文证据 |
| 问题、人工决定、成果修订 | 业务模块 | 必核问题阻断确认；保留时间、操作来源、原值、新值和依据；不建立用户身份 |
| 模型权重 | 麒麟宿主机 | 单独制品与只读挂载，不进入日常代码镜像；记录哈希和兼容组合 |

新业务契约从零定义。业务字段的证据引用至少包含业务文档 ID、MinerU 文档引用、解析修订/tier、定位器、页/块标识、可用 bbox 与**冻结的原文片段**；对外只能通过统一业务 API 读取，不能把 Doclib 内部路径直接交给浏览器或 Skill。P2 实测确认公开 locator 只有 doc/tier/page/block/char，**不含 parse_id**；重解析会创建新的解析 ID。因此 locator 只能用于当前文档导航，不能单独充当不可变证据；业务库必须保存解析 ID、当时片段与可用坐标的快照，已确认成果不因重解析静默改变。

模板第一步采用不可变版本快照：四类默认模板固定为公文、论文、研究报告、报纸，支持新建自定义模板与追加版本；字段目前仅有 `text`、`date`、`list`、必填和顺序，未声明正则或置信阈值。开放业务 API 可列出、创建、更新自定义模板、查询旧版与停用自定义模板；内置默认模板不能原地修改，需新建自定义模板。模板管理**不关联用户、角色、所有者或审批权限**。上传业务文档时可以传 `template_code`，事务内绑定当时启用的模板版本；不传则保持未分类，系统不猜测文档类型。之后模板更新或停用不改写已绑定的文档。业务 SQLite 原型现为 schema 6，旧原型库不做迁移或自动删除，必须使用新空库启动本轮原型；若需保留旧库应先自行归档。

字段提取初版把一次运行绑定到“业务解析修订 ID + 上传时冻结的模板版本”，只按 Doclib 历史 parse ID 逐页读取，明确匹配“字段标签：值”行；匹配值必须存在于同一修订的服务端冻结证据片段中。候选标为 `label_rule` 且始终未确认，不给未经标定的置信分数。扫描全页后才生成“必填缺失”或“多候选冲突”阻断问题；如果解析批次没有覆盖 Doclib 记录的文档全部页，则只生成文档级 `coverage_incomplete`，**不推断必填缺失**。读取中断、来源不符或页面截断时运行失败，失败的部分候选不会作为 API 结果展示。当前规则只是可追溯的提取基础，不等于复杂文档抽取准确率已验收；`date/list` 值尚未标准化，结构/表格/低置信问题仍待实现。

提取现由持久队列在业务 API 后台执行：`POST .../extractions` 返回 202 和 `queued` 运行 ID；worker 在独立线程中从 SQLite 事务认领，按页续租，并在完整扫描后原子标记完成。服务异常退出后，租约过期可由新进程重领同一运行；重领先清除上一尝试的未确认候选，旧租约令牌不可再发布候选或完成结果，最多尝试三次。HTTP 读取得到 `queued/running/done/failed`，失败运行的部分候选不作为结果展示。业务 API 和提取线程各持有独立 DoclibClient；模型仍只在 Doclib worker。当前重领策略是**从第一页重算**而非页级断点，旧尝试可能留下不被结果引用的证据快照；3 分钟租约意味着崩溃后不会立即重试。它满足单节点原型的请求隔离与恢复，不等于已完成多节点吞吐、断点续跑或容量验收。

复核与成果初版采用追加式字段决定、问题解决记录和审计事件：候选本身永远不自动进入成果；每个纳入成果的字段都必须由 Web/Skill/API 来源显式决定，并引用**同一解析修订**的冻结证据。接受原候选记 `candidate_acceptance`；改写值记 `manual_correction`，须填原因，不能把规范化值伪装成原文逐字摘录。记录每次决定的旧值、新值、来源和时间；来源不是个人身份。必填缺失只能在补充字段决定后解决，冲突问题可选择或附原因忽略；`coverage_incomplete` 无法人为豁免。只有提取完成、阻断问题全部处理、必填字段都有明确决定时才能确认。确认生成不可变的成果版本快照，后续更正生成新版本，不覆盖旧版。当前成果仅包含明确复核的字段；更细的结构编辑、导出格式、多人并发与签名式个人追责不在已实现范围。业务 SQLite 原型现为 schema 6；没有旧原型迁移。

证据查询进一步区分**冻结事实**与**当前导航**：`GET /api/business/evidence/{id}` 永远返回业务库中该快照的原文片段；另以当前 Doclib 内容做只读核验，返回 `current_match`、`changed` 或 `unavailable`。`current_match` 只表示现在同一定位器读到的内容哈希一致，**不证明** Doclib 对应的是原 parse ID；`changed/unavailable` 时 UI/Skill 不可声称能可靠跳回当初原文。修订列表和证据列表仅来自业务库，不泄漏 Doclib 内部 parse ID 或本地文件路径。

为解决写入侧版本绑定，fork 的 Doclib 公共契约增加 `read_parse_content(parse_id, locator)`：它只从指定已完成解析批次的持久 JSON 读取，缺失时失败，不回退到同文档新批次。业务 API 的 `POST /api/business/revisions/{id}/evidence` 只接受定位器，服务端用修订中保存的 parse ID 读取原文、核对源 SHA-256/tier/short ID/定位器并冻结片段，拒绝客户端提交任意片段。Doclib 自动压缩会删除/重写旧批次；业务 Compose 将其显式关闭以保留修订。即便如此，人工清理、业务源文件删除和存储故障仍可能使历史批次不可读；已冻结证据不会因此静默改写。此处以额外磁盘占用换取历史证据可追溯性，容量和保留期限需在麒麟现场验收。

业务身份契约：每次创建的业务文档分配独立的不透明 ID；原文件 SHA-256 是内容身份，不能替代业务 ID，因为同一内容可以属于不同业务任务。业务文档保存不可变原文的存储键、原文件名、SHA-256 和创建时间；绝对宿主路径只在服务端解析，不出现在前端/Skill 响应。已完成的解析修订另有业务修订 ID，引用 Doclib parse ID、实际 tier、源 SHA-256、生产者代码/模型版本；排队/失败状态由持久任务实体承载。重解析只新增修订，不覆盖旧修订。证据快照绑定业务文档和修订，保存 locator、可用页/块/bbox、原文片段及片段哈希；定位器失效时仍能展示冻结片段，但必须明确标记“无法回跳原文”，不得冒充仍可定位。确认成果引用特定证据快照，不随当前 Doclib 解析结果漂移。业务删除按保留策略清理引用，不能把 `forget_path` 当作业务删除。P3 已实现这些记录的初版 SQLite 存储；证据真实性串行化、删除和跨资源事务仍待实现与测试。

业务前端的持久读取契约已补齐第一组：`GET /api/business/documents` 返回按创建时间倒序的分页文档及最新入库任务，可按模板/任务状态筛选；`GET /api/business/capabilities` 返回实际上传限额、可解析扩展名和档位分组，不要求前端猜测配置。`GET /api/business/documents/{id}/source` 只接受业务 ID，从服务端存储键解析原件并复核大小/SHA-256；PDF 和图片可内联预览，HTML/Office 等仅作为附件下载，响应禁止 MIME 嗅探、不缓存，也不暴露存储键或宿主路径。它们仍属于**开放 API**，不是访问授权层；浏览器能否预览还要单独验收，不把 Office 冒充为可精确定位的 PDF。

## 模块与运行角色

```text
浏览器 ─────┐
            ├── 业务 Web/API ── 业务库（任务、模板、复核、成果、审计）
自有 Skill ─┘        │
                     └── DoclibClient / 内部文档接口
                               │
                         MinerU Doclib 服务（唯一写入者）
                               │
                         MinerU 本地解析与 GPU 推理
                               │
                         只读模型目录 + 持久文档数据目录
```

`mineru.doclib` 已公开 `DoclibClient`、`DoclibInterface` 与类型化响应；优先在业务模块使用它。Doclib 具备实例所有权锁，不允许 Web 与 worker 各自直接写同一个 Doclib 数据目录。初版先验证 Client 的文档身份、parse/search/read/locator、删除和重启语义；仅针对公开接口不能覆盖的需求，集中扩展 MinerU 平台代码。

P2 发现 `ensure_parse` 接收的是 **worker 可访问的本地绝对路径**，不是文件字节上传。业务 API 应将原文件写入专用、不可变的共享上传目录，worker 以只读方式挂载同一目录并调用公开 `DoclibClient`；业务 API 不能向 Doclib 提交自己容器里独有的路径。共享目录与 Doclib 数据目录分别管理，不把原文件塞进代码镜像或模型目录。`mineru.business.documents.DoclibGateway` 当前先执行共享路径、格式档位、本地模式和文件哈希校验。

上传目录由 `ImmutableUploadStore` 执行限额流式写入、同步、完成后原子发布，按随机存储键保留每次上传的独立路径；同字节 SHA-256 可相同，但业务记录不合并。临时文件后缀不属于 Doclib 可解析格式，Doclib 不应扫描未完成上传。文件权限设为只读属于误操作防线，**不是防同 UID/管理员篡改的安全边界**；worker 必须只读挂载、上传目录只允许业务 API 写入，且 Doclib 提交前后仍校验原文哈希。业务 API 应将存储记录写入业务事务库；若事务失败，须有孤儿文件清理机制，不能把单独的文件发布视为完整业务提交。

逻辑上是**一套源码、一套产品**。物理上推荐业务 Web/API 与文档/GPU 工作进程分开运行，避免界面改动扰动显存中的模型；这通常产生两个代码镜像，但镜像数量不是交付目标。官方 WebUI 可保留作内部调试，不作为面向业务用户的主界面。官方 Router、独立 OpenAI-compatible VLM Server 不是单机初版必需服务。前端与自有 Skill 必须调用同一业务 API，禁止 Skill 直连原始 MinerU 结果并跳过复核状态。

业务 Web 以原生 JS/CSS 模块构建，无前端第三方依赖；同源挂载在业务 API 服务上。前端读取服务能力而非硬编码上传限额，PDF/图片选择四档，Office 等原生格式固定 Flash；逐文件反馈、任务状态轮询和重试直接使用开放业务 API。构建产物 `dist/` 不进 Git，但逐文件哈希写入 `asset-manifest.json`；业务镜像在构建时校验该 manifest 哈希，发布清单再次核对静态文件、manifest 与镜像标签。

第二组 Web 实现把修订/提取运行、冻结证据、机器候选、显式复核决定、问题处理、确认成果版本与 JSON/Markdown 导出接入同一开放业务 API。机器候选明确标为未确认；未处理问题和未决定的必填字段阻止确认；原文定位仅在当前内容与冻结片段一致时提供 PDF 页跳转尝试，变化或不可用时只展示冻结证据，不能声称历史批次仍可精确导航。审计显示操作来源，不代表个人身份。**P4 仍未完成**：搜索/结构树、修订差异、字段高亮与双向联动、模板管理/统计等页面以及真实文件端到端验证仍待补齐。Skill 使用界面也尚未实现。

## 核心流程

1. 上传原文，做格式/大小/安全校验与哈希计算，建立业务文档身份并交给 Doclib 入库。
2. 按当前部署能力选择解析策略：PDF/图片支持四档；Office/OpenDocument/EPUB/OFD/HTML/CSV 等原生文档使用 Flash。记录实际 tier、模型组合和源码版本。
3. 业务模板从解析块中生成字段候选与证据；质量规则生成必核/可选问题。机器结果一律标记为未确认。
4. 复核工作台联动原文、结构、字段、问题和定位器；人工修改可追溯。必核问题处理完才能确认结果。
5. 搜索和渐进式读取优先复用 Doclib；业务层在返回之前加“原文/机器结果/人工确认”的状态语义。
6. 成果导出、前端与自有 Skill 读取统一的业务结果版本；渲染格式只按实际已验证的接口能力开放。

## 生产部署与更新

**完全断网是默认工况。** 联网准备环境生成精确版本的 x86_64 基础/运行镜像、离线依赖包、模型目录与 SHA-256 清单；经批准介质导入麒麟。生产运行禁用远程解析、远程 VLM、在线模型下载和在线依赖安装。模型下载针对目标 Torch + vLLM 配置，运行时设 `model.source=local` 和明确的 `model.base_dir`；启动前校验模型完备性，再用真实文档解析验证。具体 GPU/驱动/CUDA 兼容性以目标设备实测为准。

官方 Dockerfile 在构建时从包索引安装 MinerU 并下载权重，不用于最终交付。我们维护 fork 专用 Dockerfile：安装**本地 fork 源码**、使用离线依赖、把模型目录排除构建上下文。Mac 日常只传必要源码/锁文件；麒麟利用预置依赖本地构建受影响代码镜像。模型目录和文档/业务数据目录持久保存，不随重建覆盖。若上游更新了代码，合入确定提交并回归后重建受影响镜像；只有模型本身升级时才单独导入新模型制品。

## 安全和质量门槛

- 业务系统无登录、无用户/角色/令牌权限。前端与自有 Skill 均使用同一开放业务 API；任何能访问业务 API 的客户端都能操作业务文档，因此部署时只在物理隔离环境的受控内网暴露业务端口。Doclib 仅在容器内部网络开放，不能直接对业务网络发布。
- 人工确认是成果状态规则，不是身份权限规则；没有身份信息时，操作记录只能标记 Web/Skill 等来源和时间，不能声称可追责到个人。
- 未确认的字段和 Agent 回答须明确标记；不允许从机器候选直接伪装成已确认成果。
- 模型、依赖、源码和配置分别锁定版本/哈希；发布清单描述可兼容组合，支持回退。
- 旧原型的合成黄金数据仅可作为需求示例；不代表新系统准确率。用公文、论文、研究报告、报纸的脱敏真实样本与人工标注测字段、结构、证据、复核成本与吞吐；手写、跨页表格、印章/水印专项验收。
- 麒麟断网启动、业务重启、Doclib 重启、模型缺失、解析失败、重复上传、重解析和恢复重试都要有自动化或现场测试记录。

## 尚待原型确认的设计点

1. DoclibClient 的持久文档身份、引用稳定性与删除语义是否足够支撑业务成果版本。
2. Doclib 的本地 socket/TCP 通道在两个容器之间如何安全暴露，单实例写入锁与重启恢复如何配合。
3. Office 等格式的原文预览、定位器几何信息与 PDF/图片是否一致；不能在未验证前承诺相同的 bbox 体验。
4. P3 初版采用单机 SQLite，独立于 Doclib 数据库，显式事务和外键约束；它不是已经通过并发容量/在线备份验收的生产承诺。若现场规模超出单机约束，按 P3 的存储接口替换，不能让前端/Skill 直连数据库。
5. 第三方许可证与对外标识义务由项目方在上线前核对；此文档不是法律意见。
