# MinerU 4 业务文档平台架构设计

状态：设计基线，待原型验证后固化实现细节。仓库 `itsallsame/MinerU` 的 `master` 是唯一开发主线；不保留旧 3.4/V1 API、数据或代码兼容。

## 目标

基于 MinerU 4.0.6 源码构建一套离线业务文档平台。MinerU 提供解析、档位、文档库、缓存、搜索、续读和定位器；本产品提供业务模板、字段提取、质量检查、原文证据、人工复核、确认、成果、前端和自有 Skill。Mac 仅开发测试，生产是完全物理隔离的银河麒麟 x86_64 + NVIDIA。

## 核心概念与数据所有权

| 概念 | 所有者 | 关键约束 |
| --- | --- | --- |
| 原文件与 MinerU 文档身份 | Doclib | 文档内容与索引唯一来源；业务系统不复制全文索引 |
| 解析修订 | MinerU + 业务引用 | 保存实际 tier、生产者版本、输入哈希与可复查定位器；重新解析不覆盖已确认依据 |
| 业务文档/任务 | 业务模块 | 关联 Doclib 文档身份；独立的可恢复业务状态，不使用 V1 临时 job ID 当业务 ID |
| 模板版本和候选字段 | 业务模块 | 公文、论文、研究报告、报纸和自定义类型；字段需绑定原文证据 |
| 问题、人工决定、成果修订 | 业务模块 | 必核问题阻断确认；保留时间、操作来源、原值、新值和依据；不建立用户身份 |
| 模型权重 | 麒麟宿主机 | 单独制品与只读挂载，不进入日常代码镜像；记录哈希和兼容组合 |

新业务契约从零定义。业务字段的证据引用至少包含业务文档 ID、MinerU 文档引用、解析修订/tier、定位器、页/块标识、可用 bbox 与**冻结的原文片段**；对外只能通过统一业务 API 读取，不能把 Doclib 内部路径直接交给浏览器或 Skill。P2 实测确认公开 locator 只有 doc/tier/page/block/char，**不含 parse_id**；重解析会创建新的解析 ID。因此 locator 只能用于当前文档导航，不能单独充当不可变证据；业务库必须保存解析 ID、当时片段与可用坐标的快照，已确认成果不因重解析静默改变。冻结片段保存 SHA-256，并在读取、候选写入、复核决定及成果确认时核对；不一致时拒绝作为有效证据。该哈希能发现单独的意外内容损坏，不是防数据库管理员同时改写内容和哈希的签名机制。

模板第一步采用不可变版本快照：四类默认模板固定为公文、论文、研究报告、报纸，支持新建自定义模板与追加版本；字段目前仅有 `text`、`date`、`list`、必填和顺序，未声明正则或置信阈值。开放业务 API 可列出、创建、更新自定义模板、查询旧版与停用自定义模板；内置默认模板不能原地修改，需新建自定义模板。模板管理**不关联用户、角色、所有者或审批权限**。上传业务文档时可以传 `template_code`，事务内绑定当时启用的模板版本；不传则保持未分类，系统不猜测文档类型。之后模板更新或停用不改写已绑定的文档。业务 SQLite 当前为 schema 13，旧原型库不做迁移或自动删除，必须使用新空库启动；若需保留旧库应先自行归档。

字段提取把一次运行绑定到“业务解析修订 ID + 上传时冻结的模板版本”，按 Doclib 历史 parse ID 逐页读取，明确匹配“字段标签：值”行；匹配值必须存在于同一修订的服务端冻结证据片段中。显式标签候选标为 `label_rule`；Markdown 加粗标签可把冒号放在标记内或外，论文模板的“关键词”字段还接受独立行的英文 `Keywords:`，但不会把普通正文或无值章节标题推断为关键词。关键词列表暂保留原文分隔符与整体字符串，不拆分或规范化。两列 Markdown 表格仅当存在列分隔行、字段标签完整匹配冻结模板且值处于数据行时，生成 `table_row` 候选；多列表格、无分隔行及表头不猜值，页级冻结证据不冒充精确单元格定位。对于模板的 `title` 文本字段，在所有扫描页均无显式标题标签时，还可读取第一页原生 `doc_title` 块的完整历史内容，生成 `native_doc_title` 候选，不使用结构预览当证据。对于模板的 `abstract` 文本字段，若扫描页均无显式“摘要：值”，则可从第一页精确 `摘要`/`Abstract` Markdown 标题后的首个完整纯文本段落提出 `section_heading` 候选；页码、修订与冻结证据仍逐项绑定，不跨段猜测。四种候选均始终未确认，不给未经标定的置信分数。扫描全页后才生成“必填缺失”或“多候选冲突”阻断问题；如果解析批次没有覆盖 Doclib 记录的文档全部页，则只生成文档级 `coverage_incomplete`，**不推断必填缺失**。读取中断、来源不符或页面截断时运行失败，失败的部分候选不会作为 API 结果展示。当前规则只是可追溯的提取基础，不等于复杂文档抽取准确率已验收；`date/list` 值尚未标准化，复杂表格/低置信问题仍待实现。系统保持无登录、无用户、无角色、无权限管理的开放形态；人工复核是内容状态，不是身份授权。

提取现由持久队列在业务 API 后台执行：`POST .../extractions` 返回 202 和 `queued` 运行 ID；worker 在独立线程中从 SQLite 事务认领，按页续租，并在完整扫描后原子标记完成。服务异常退出后，租约过期可由新进程重领同一运行；重领先清除上一尝试的未确认候选，旧租约令牌不可再发布候选或完成结果，最多尝试三次。HTTP 读取得到 `queued/running/done/failed`，失败运行的部分候选不作为结果展示。业务 API 和提取线程各持有独立 DoclibClient；模型仍只在 Doclib worker。当前重领策略是**从第一页重算**而非页级断点，旧尝试可能留下不被结果引用的证据快照；3 分钟租约意味着崩溃后不会立即重试。它满足单节点原型的请求隔离与恢复，不等于已完成多节点吞吐、断点续跑或容量验收。

业务文档任务另有后台恢复扫描，不依赖用户逐个打开任务详情：业务 API 生命周期启动独立的 `DocumentTaskWorker` 和独立 Doclib 客户端，按业务任务 ID 做有界 keyset 扫描。`uploaded`、`submitting` 和提交响应未知的 `doclib_submission_failed` 会按持久提交世代重交同一请求；`submitted` 轮询解析状态并在完成后原子生成修订；`cancel_requested` 重放 Doclib 释放结果。Doclib 在已建立连接后出现读取超时等 `httpx.RequestError` 时也遵循此状态机：提交按同一世代恢复，解析/原件元数据轮询保留已提交状态，取消保留待确认意图，不把网络未知结果当成解析失败或已停止。明确的解析失败不会自动 force 重试，仍由业务重试入口决定。缺失的保留原件记为 `source_unavailable`；此类失败以及已完成/已取消任务不会进入后台热循环。业务与 Doclib 数据库无跨库事务，故重放仍依赖 Doclib 的世代/释放墓碑；扫描线程本身不声称模型任务抢占或目标麒麟故障恢复已验收。API 仍为开放系统，无用户或权限管理。

2026-09-24 解析完成触发字段提取：对上传时绑定模板的文档，业务库现在在**同一个事务**内创建/复用已完成解析修订、将任务置为 `done`、并排入该修订的首次字段提取运行。任何入队写入失败都回滚任务完成与修订，不留下半成品；并发刷新和重放只生成一次首次运行。未绑定模板的文档不自动提取，人工再次生成候选仍可创建新运行。提取线程处理规则候选，Web 与自有 Skill 仅展示 `machine_unconfirmed`；用户仍须逐字段决定并处理阻断问题，自动提取绝不等于自动确认成果。真实 Doclib HTML 联调已验证标题候选和冻结证据链；这不代表四类真实复杂文档的准确率或麒麟 GPU 验收。

复核与成果初版采用追加式字段决定、问题解决记录和审计事件：候选本身永远不自动进入成果；每个纳入成果的字段都必须由 Web/Skill/API 来源显式决定，并引用**同一解析修订**的冻结证据。接受原候选记 `candidate_acceptance`；改写值记 `manual_correction`，须填原因，不能把规范化值伪装成原文逐字摘录。记录每次决定的旧值、新值、来源和时间；来源不是个人身份。必填缺失只能在补充字段决定后解决，冲突问题可选择或附原因忽略；`coverage_incomplete` 无法人为豁免。只有提取完成、阻断问题全部处理、必填字段都有明确决定时才能确认。确认生成追加式成果版本快照，后续更正生成新版本，不覆盖旧版。成果字段 JSON 保存 SHA-256；详情、版本列表和再次确认均核对现有版本，损坏时拒绝输出或生成新版本，避免单独的内容损坏被静默当成有效成果。这不是抵御数据库管理员同时改写内容与哈希的签名机制。当前成果仅包含明确复核的字段；更细的结构编辑、多人并发与签名式个人追责不在已实现范围。业务 SQLite 当前为 schema 13；没有旧原型迁移。

证据查询进一步区分**冻结事实**与**当前导航**：`GET /api/business/evidence/{id}` 永远返回业务库中该快照的原文片段；另以当前 Doclib 内容做只读核验，返回 `current_match`、`changed` 或 `unavailable`。`current_match` 只表示现在同一定位器读到的内容哈希一致，**不证明** Doclib 对应的是原 parse ID；`changed/unavailable` 时 UI/Skill 不可声称能可靠跳回当初原文。修订列表和证据列表仅来自业务库，不泄漏 Doclib 内部 parse ID 或本地文件路径。

为解决写入侧版本绑定，fork 的 Doclib 公共契约增加 `read_parse_content(parse_id, locator)`：它只从指定已完成解析批次的持久 JSON 读取，缺失时失败，不回退到同文档新批次。业务 API 的 `POST /api/business/revisions/{id}/evidence` 只接受定位器，服务端用修订中保存的 parse ID 读取原文、核对源 SHA-256/tier/short ID/定位器并冻结片段，拒绝客户端提交任意片段。Doclib 自动压缩会删除/重写旧批次；业务 Compose 将其显式关闭以保留修订。即便如此，人工清理、业务源文件删除和存储故障仍可能使历史批次不可读；已冻结证据不会因此静默改写。此处以额外磁盘占用换取历史证据可追溯性，容量和保留期限需在麒麟现场验收。

业务身份契约：每次创建的业务文档分配独立的不透明 ID；原文件 SHA-256 是内容身份，不能替代业务 ID，因为同一内容可以属于不同业务任务。业务文档保存不可变原文的存储键、原文件名、SHA-256 和创建时间；绝对宿主路径只在服务端解析，不出现在前端/Skill 响应。已完成的解析修订另有业务修订 ID，引用一组 Doclib parse ID 与各自页范围、实际 tier、源 SHA-256、生产者代码/模型版本；排队/失败状态由持久任务实体承载。重解析只新增修订，不覆盖旧修订。证据快照绑定业务文档和修订，保存 locator、可用页/块/bbox、原文片段及片段哈希；定位器失效时仍能展示冻结片段，但必须明确标记“无法回跳原文”，不得冒充仍可定位。确认成果引用特定证据快照，不随当前 Doclib 解析结果漂移。业务删除按保留策略清理引用，不能把 `forget_path` 当作业务删除。P3 已实现这些记录的初版 SQLite 存储；证据真实性串行化、删除和跨资源事务仍待实现与测试。

长 PDF 修订契约：业务提交 PDF 时明确请求 `page_range=all`；Doclib 可把同一文档拆成多个完成批次，因此一个业务修订聚合无交叠、同 SHA-256/short ID/tier 的批次，并公布合并页范围和 Doclib 实际 short ID，不暴露各批次内部 ID。任务只有在批次覆盖 Doclib 记录的每一页时才完成；缺页或批次冲突会失败且强制重新解析。历史渐进读取、冻结证据和字段提取按 locator 所在页选择对应批次，不把最后一批误当作整份文档。schema 7 为此新增批次映射；没有旧库迁移。

业务前端的持久读取契约已补齐第一组：`GET /api/business/documents` 返回按创建时间倒序的分页文档及最新入库任务，可按模板/任务状态筛选；`GET /api/business/capabilities` 返回实际上传限额、可解析扩展名和档位分组，不要求前端猜测配置。`GET /api/business/documents/{id}/source` 只接受业务 ID，从服务端存储键解析原件并复核大小/SHA-256；PDF 和图片可内联预览，HTML/Office 等仅作为附件下载，响应禁止 MIME 嗅探、不缓存，也不暴露存储键或宿主路径。它们仍属于**开放 API**，不是访问授权层；浏览器能否预览还要单独验收，不把 Office 冒充为可精确定位的 PDF。

## 模块与运行角色

```text
浏览器 ─────┐
            ├── 业务 Web/API ── 业务库（任务、模板、复核、成果、审计）
自有 Skill ─┘        │
                     └── DoclibClient / 内部文档接口
                               │
                         MinerU Doclib 服务（唯一写入者）
                               │
                         MinerU 本地解析与 GPU 推理
                               │
                         只读模型目录 + 持久文档数据目录
```

`mineru.doclib` 已公开 `DoclibClient`、`DoclibInterface` 与类型化响应；优先在业务模块使用它。Doclib 具备实例所有权锁，不允许 Web 与 worker 各自直接写同一个 Doclib 数据目录。初版先验证 Client 的文档身份、parse/search/read/locator、删除和重启语义；仅针对公开接口不能覆盖的需求，集中扩展 MinerU 平台代码。

P2 发现 `ensure_parse` 接收的是 **worker 可访问的本地绝对路径**，不是文件字节上传。业务 API 应将原文件写入专用、不可变的共享上传目录，worker 以只读方式挂载同一目录并调用公开 `DoclibClient`；业务 API 不能向 Doclib 提交自己容器里独有的路径。共享目录与 Doclib 数据目录分别管理，不把原文件塞进代码镜像或模型目录。`mineru.business.documents.DoclibGateway` 当前先执行共享路径、格式档位、本地模式和文件哈希校验。

上传目录由 `ImmutableUploadStore` 执行限额流式写入、同步、完成后原子发布，按随机存储键保留每次上传的独立路径；同字节 SHA-256 可相同，但业务记录不合并。临时文件后缀不属于 Doclib 可解析格式，Doclib 不应扫描未完成上传。文件权限设为只读属于误操作防线，**不是防同 UID/管理员篡改的安全边界**；worker 必须只读挂载、上传目录只允许业务 API 写入。提交网关在调用 Doclib 前将当前原文件哈希与业务记录的注册哈希比较，损坏则任务终止为 `source_integrity_failed`，即使 Doclib 暂时不可用也不能把损坏文件作为可重试提交；调用后仍复核原文哈希和 Doclib 响应的文件身份。解析完成、创建业务修订前再次核对保留原件的大小及 SHA-256；丢失或损坏则任务失败，不生成修订和自动字段提取。原件下载入口使用同一核对逻辑，但文件系统上的同 UID/管理员并发改写仍不在这层哈希检查的防护范围。业务 API 应将存储记录写入业务事务库；若事务失败，须有孤儿文件清理机制，不能把单独的文件发布视为完整业务提交。

逻辑上是**一套源码、一套产品**。物理上推荐业务 Web/API 与文档/GPU 工作进程分开运行，避免界面改动扰动显存中的模型；这通常产生两个代码镜像，但镜像数量不是交付目标。官方 WebUI 可保留作内部调试，不作为面向业务用户的主界面。官方 Router、独立 OpenAI-compatible VLM Server 不是单机初版必需服务。前端与自有 Skill 必须调用同一业务 API，禁止 Skill 直连原始 MinerU 结果并跳过复核状态。

业务 Web 以原生 JS/CSS 模块构建，无前端第三方依赖；同源挂载在业务 API 服务上。前端读取服务能力而非硬编码上传限额，PDF/图片选择四档，Office 等原生格式固定 Flash；逐文件反馈、任务状态轮询和重试直接使用开放业务 API。构建产物 `dist/` 不进 Git，但逐文件哈希写入 `asset-manifest.json`；业务镜像在构建时校验该 manifest 哈希，发布清单再次核对静态文件、manifest 与镜像标签。

第二组 Web 实现把修订/提取运行、冻结证据、机器候选、显式复核决定、问题处理、确认成果版本与 JSON/Markdown 导出接入同一开放业务 API。机器候选明确标为未确认；未处理问题和未决定的必填字段阻止确认；原文定位仅在当前内容与冻结片段一致时提供 PDF 页跳转尝试，变化或不可用时只展示冻结证据，不能声称历史批次仍可精确导航。审计显示操作来源，不代表个人身份。后续已增设业务文档检索、历史解析渐进读取、原生结构树、块候选、解析修订逐页文本差异、字段冻结证据高亮、PDF/图片页级原文双向联动、质量统计与全局审计。原件预览先用同源 HEAD 复用服务端文件大小及 SHA-256 核验；失败不展示下载/预览链接，图片加载失败再次撤下预览，且 GET 仍独立校验。PDF 内嵌查看器在 HEAD 后的晚发失败无法保证可观测，不作为原文已成功显示的证明。**P4 仍未完成**：其余异步错误恢复、键盘与焦点等体验项，以及真实文件端到端质量验证仍待补齐。

自有 `business-documents` Skill 位于本 fork 的 `skills/business-documents/`，随代码分发、在隔离区离线导入 Agent；不是官方 `mineru` Skill。其零第三方依赖脚本与 Web 调用同一业务 API，上传前查询服务能力，读取任务、最新修订/提取、冻结证据及确认成果，也能进行业务检索、历史结构树/页块级检索与修订绑定的定位器续读；机器候选和确认成果分开呈现。`evidence` 命令在冻结证据响应外补充同源业务 Web 的 `#evidence=ID` 深链；Web 先通过业务 API 检查证据所属业务文档和修订，再展示冻结片段，定位变化时仍不允许可靠原文跳转。无模板文档也能查看已冻结证据。Skill 的任务重试、取消和手动再提取都需显式写入确认；POST 结果不明时只读查询同一任务或修订的提取运行并标记结果未确认，不能自动再 POST。修订的运行列表不能证明某次手动再提取成功，因为当前接口没有该写操作的请求幂等键。Skill 不提供自动确认命令，也不直接调用 Doclib、官方 CLI、模型服务或远程解析。P5 的 Mac 契约与本地联通已通过，真实样本和目标麒麟环境仍归 P6 验收。

第三组实现补齐业务范围内的两条只读契约：`GET /api/business/search` 复用 Doclib 当前索引，但只返回能映射到**已完成业务解析修订**的业务文档，省略 Doclib 文件路径，并标记 `current_index_unconfirmed`。同字节不同业务文档分别列出；一次最多扫描 500 个 Doclib 命中，`scan_complete=false` 明示检索可能未穷尽。Doclib 检索只有文档级片段、没有页块定位器，片段不得当作冻结证据或精确引用。`GET /api/business/revisions/{id}/content` 按页选择业务修订保存的历史 parse ID 读取指定 locator，核对源 SHA-256、short ID、tier 与请求定位器，返回 `historical_parse_unconfirmed`、有界内容和安全续读 locator；不返回 Doclib parse ID 或 asset 路径。它是机器解析文本，不等于人工确认或不可变证据。Web 与自有 Skill 都只访问这两条业务 API。后续页块候选列表、结构树、模板管理、质量统计和修订逐页文本差异已补齐；真实样本端到端和目标机验收仍开放。

第四组补充修订内页检索：`GET /api/business/revisions/{id}/search` 在指定历史业务修订上逐页读取，每次最多扫描 25 页，以 `next_page` 续扫；每页只返回首个文本命中及页定位器，状态固定为 `historical_parse_unconfirmed`。该接口在页面内容截断、身份不符或历史批次不可读时失败，不把部分扫描误报为“无结果”。Web 可从文档级预览进入历史页搜索与读取；自有 Skill 的 `search-pages` 使用同一业务 API。页命中**不是冻结证据或人工确认结论**，也没有块级定位与完整召回保证；P4 的页块证据列表仍未完成。

模板管理 Web 已接入现有开放业务 API：展示内置和自定义模板，内置模板只读；自定义模板支持创建、按字段顺序配置代码/名称/类型/必填、新增不可变版本及停用。停用前要求页面确认，停用后新上传不能再选，旧文档绑定的版本不改写。Web 不引入用户、角色、所有者或审批权限。当前字段类型仍只支持 `text/date/list`，不包含正则、标准化、置信阈值或结构编辑；后续质量统计、结构树和页块候选已实现，但不代表全 P4 完成。

历史标题目录新增 `GET /api/business/revisions/{id}/outline`：按业务修订的历史 parse 批次读取 Markdown，识别 ATX 标题级别并排除代码围栏，每次最多 25 页、以 `next_page` 续扫；任一页截断或身份不符即报错，不输出不完整的“完整目录”。Web 目录项可读到所在页，自有 Skill `outline` 走同一业务 API。此目录是**Markdown 标题的派生视图**，不是 Doclib 原生模型块树；只有页级定位，不保证标题完整或块级证据。原生块树另见下一段，标题目录本身不充当 FE-023 的完成依据。

原生块树从 Doclib 公共接口 `read_parse_structure(parse_id,page_no)` 读取持久化 Middle JSON 的指定历史批次与页，不让业务服务直接打开 Doclib 私有文件。返回模型父子块类型、原生层级路径、可用标题级别/bbox、文本类块的 200 字符预览和顶层块定位器；子块只继承其顶层块定位器，不声称子块精确定位。每页最多 500 个顶层块、2000 个总节点、16 层，越界则拒绝而非悄悄截断。业务 API `/api/business/revisions/{id}/structure?page_no=...` 按修订页映射挑选批次并递归核对 SHA-256、short ID、tier、页码、节点路径和顶层定位器，不外露 parse ID/宿主路径。Web 与自有 Skill 都通过该业务 API 查看原生树。FE-023 按“展示模型实际存在的解析结构树”完成；模型未提供的表格单元格层级、子节点精确定位及人工确认不在其完成声明内。

块级候选搜索新增 Doclib 公共接口 `search_parse_blocks(parse_id,page_no,query)`：只读指定历史批次的一页持久模型树，将行内与子块文字归到顶层块；不搜索图片载荷、URL 或内部路径。每页最多 500 顶层块、2000 节点、16 层、100 万原始字符和 100 个命中，越界失败而非输出不完整的“无命中”。业务 API `/api/business/revisions/{id}/search-blocks` 按修订页映射调用，递归扫描每次最多 25 页，以 `next_page` 续扫，核验身份和块定位器，总命中超过 200 报错。Web 的检索结果显示明确的“机器解析候选，未人工确认”块列表，可读取历史块；用户显式点击“冻结此块原文”后才调用既有证据快照 API，并进入证据复核。自有 Skill 的 `search-blocks` 走相同业务 API，但不自动冻结或确认。FE-018 以候选列表和显式冻结入口为范围完成；不存在无限量召回、子块精确定位或自动人工确认的承诺。

质量统计通过 `GET /api/business/quality-stats` 对业务 SQLite 做同一只读事务内的聚合，Web 折叠面板按需读取并可手动刷新。文档按业务文档 ID 计数，同一字节多次上传仍是多份业务文档；任务、解析修订、提取运行、阻断问题和不可变成果版本分别按各自记录计数，均不是当前文档数。已确认提取运行按不同运行 ID 去重，成果版本按全部版本计数；待处理包含上传/已提交解析任务及排队/运行中的提取运行；未处理问题只算 `open`。这是流程存量视图，不是解析准确率、字段质量评分或人工标注验收；不含用户、角色、操作者身份。

全局审计页通过 `GET /api/business/audit?limit=...&before=...` 按审计事件实际插入顺序倒排、最多 100 条/页；下一页游标是当前最后一条事件 ID，查询时解析为内部 rowid，不对外暴露数据库位置。新事件追加不会使旧页偏移。每条事件关联业务文档 ID/名称和业务修订 ID，可从 Web 回到具体提取运行；只显示既有动作、来源、前后值和原因，前端使用纯文本渲染。`source=web/skill/api` 表示调用入口，不构成用户或操作者身份；没有登录、角色或权限控制。当前审计只覆盖字段决定、问题处理与成果确认，不把上传、解析或读取伪称为已审计。审计行仍依赖单节点 SQLite 的持久性，不是防数据库管理员篡改的签名审计。

解析修订差异通过 `GET /api/business/revisions/{id}/diff?other_revision_id=...` 比较**同一业务文档**的两次历史修订；服务端按各自页到实际 Doclib parse 批次的映射读取整页，逐字比较机器解析文本，返回 `same/changed/only_left/only_right` 及两版页定位器，不返回全文或内部 parse ID。每次最多扫描 25 页，`next_page` 续扫；任一被比较页截断、身份不符或历史批次不可用则整次请求失败，不把局部文本误标为完整差异。Web 显示已扫描页数与未扫范围，可按需并排读取两版页文本，窄屏改为上下排列。这只提示解析文本差异，**不比较原生结构树、图片、bbox、字段候选或人工确认成果**；同文不同结构仍可能显示“页文本相同”。机器结果仍未人工确认，不会自动更新冻结证据或成果。

字段证据高亮沿用业务复核工作台已有的候选/决定 → `evidence_id` 关系：点击候选或已复核字段读取同一冻结证据，片段里仅把字段值**逐字匹配**的部分以文本节点 `<mark>` 标记，最多 20 处；值不在片段中（如人工规范化）时显示无逐字匹配提示，仍保留合法的证据绑定但不虚构原文文字。打开冻结证据也可反查该提取运行中关联的候选/最新决定字段并定位字段卡。当前 Doclib 定位核验为 `current_match` 且浏览器可预览 PDF/图片时才可尝试跳转原文页/原图；`changed/unavailable` 不跳。此功能不在内嵌 PDF 查看器内绘制 bbox 或文字选区。

FE-031 的双向联动采用**明确页级**契约：在 PDF 原文面板输入页码，或在单页图片面板点击“查找此图的关联字段”，复核区只列当前业务解析修订该页已经冻结的证据，再列当前提取运行里引用这些证据的候选/最新决定字段；点击可核验冻结片段并聚焦字段。反方向从字段打开冻结证据后，仅在当前 Doclib 定位与快照片段匹配时可尝试跳 PDF 页或单页原图。无冻结证据时明确为“尚无”，不推断原文无字段；修订/运行加载中或失败时不显示虚假的零关联。页码是用户显式输入或证据提供的，不宣称能监测内嵌 PDF 查看器内部滚动/文字选择，也不承诺 bbox 像素级覆盖；Office 等浏览器无法内联预览的原件仍只提供下载与冻结证据工作台。

## 核心流程

1. 上传原文，做格式/大小/安全校验与哈希计算，建立业务文档身份并交给 Doclib 入库。
   上传重试按业务请求键而非内容哈希判重：同键同意图返回原文档/任务，同键异意图冲突，新键同内容仍是新的业务文档。开放查询接口可用请求键找回已入库的文档/当前任务；Web 在当前标签页保存待核对键，刷新后先查再由用户决定是否重选原文件重试。404 仅表示查询时尚无记录，不触发新上传。键不代表操作者身份，Web/Skill 共享同一开放 API 合同。
2. 按当前部署能力选择解析策略：PDF/图片支持四档；Office/OpenDocument/EPUB/OFD/HTML/MHTML/CSV 等原生文档使用 Flash。MHTML/MHT 是受限的本地 MIME 归档解析，不启用远程抓取；它与普通 HTML 是两个后缀契约。记录实际 tier、模型组合和源码版本。
3. 业务模板从解析块中生成字段候选与证据；质量规则生成必核/可选问题。机器结果一律标记为未确认。
4. 复核工作台联动原文、结构、字段、问题和定位器；人工修改可追溯。必核问题处理完才能确认结果。
5. 搜索和渐进式读取优先复用 Doclib；业务层在返回之前加“原文/机器结果/人工确认”的状态语义。
6. 成果导出、前端与自有 Skill 读取统一的业务结果版本；渲染格式只按实际已验证的接口能力开放。

## 生产部署与更新

**完全断网是默认工况。** 联网准备环境生成精确版本的 x86_64 基础/运行镜像、离线依赖包、模型目录与 SHA-256 清单；经批准介质导入麒麟。生产运行禁用远程解析、远程 VLM、在线模型下载和在线依赖安装。模型下载针对目标 Torch + vLLM 配置，运行时设 `model.source=local` 和明确的 `model.base_dir`；启动前校验模型完备性，再用真实文档解析验证。具体 GPU/驱动/CUDA 兼容性以目标设备实测为准。

官方 Dockerfile 在构建时从包索引安装 MinerU 并下载权重，不用于最终交付。我们维护 fork 专用 Dockerfile：安装**本地 fork 源码**、使用离线依赖、把模型目录排除构建上下文。Mac 日常只传必要源码/锁文件；麒麟利用预置依赖本地构建受影响代码镜像。模型目录和文档/业务数据目录持久保存，不随重建覆盖。若上游更新了代码，合入确定提交并回归后重建受影响镜像；只有模型本身升级时才单独导入新模型制品。

## 安全和质量门槛

- 业务系统无登录、无用户/角色/令牌权限。前端与自有 Skill 均使用同一开放业务 API；任何能访问业务 API 的客户端都能操作业务文档，因此部署时只在物理隔离环境的受控内网暴露业务端口。Doclib 仅在容器内部网络开放，不能直接对业务网络发布。
- 人工确认是成果状态规则，不是身份权限规则；没有身份信息时，操作记录只能标记 Web/Skill 等来源和时间，不能声称可追责到个人。
- 未确认的字段和 Agent 回答须明确标记；不允许从机器候选直接伪装成已确认成果。
- 模型、依赖、源码和配置分别锁定版本/哈希；发布清单描述可兼容组合，支持回退。
- 旧原型的合成黄金数据仅可作为需求示例；不代表新系统准确率。用公文、论文、研究报告、报纸的脱敏真实样本与人工标注测字段、结构、证据、复核成本与吞吐；手写、跨页表格、印章/水印专项验收。
- 麒麟断网启动、业务重启、Doclib 重启、模型缺失、解析失败、重复上传、重解析和恢复重试都要有自动化或现场测试记录。

## 尚待原型确认的设计点

1. DoclibClient 的持久文档身份、引用稳定性与删除语义是否足够支撑业务成果版本。
2. Doclib 的本地 socket/TCP 通道在两个容器之间如何安全暴露，单实例写入锁与重启恢复如何配合。
3. Office 等格式的原文预览、定位器几何信息与 PDF/图片是否一致；不能在未验证前承诺相同的 bbox 体验。
4. P3 初版采用单机 SQLite，独立于 Doclib 数据库，显式事务和外键约束；它不是已经通过并发容量/在线备份验收的生产承诺。若现场规模超出单机约束，按 P3 的存储接口替换，不能让前端/Skill 直连数据库。
5. 第三方许可证与对外标识义务由项目方在上线前核对；此文档不是法律意见。
