# MinerU 4 业务文档平台架构设计

状态：设计基线，待原型验证后固化实现细节。仓库 `itsallsame/MinerU` 的 `master` 是唯一开发主线；不保留旧 3.4/V1 API、数据或代码兼容。

## 目标

基于 MinerU 4.0.6 源码构建一套离线业务文档平台。MinerU 提供解析、档位、文档库、缓存、搜索、续读和定位器；本产品提供业务模板、字段提取、质量检查、原文证据、人工复核、确认、成果、前端和自有 Skill。Mac 仅开发测试，生产是完全物理隔离的银河麒麟 x86_64 + NVIDIA。

## 核心概念与数据所有权

| 概念 | 所有者 | 关键约束 |
| --- | --- | --- |
| 原文件与 MinerU 文档身份 | Doclib | 文档内容与索引唯一来源；业务系统不复制全文索引 |
| 解析修订 | MinerU + 业务引用 | 保存实际 tier、生产者版本、输入哈希与可复查定位器；重新解析不覆盖已确认依据 |
| 业务文档/任务 | 业务模块 | 关联 Doclib 文档身份；独立的可恢复业务状态，不使用 V1 临时 job ID 当业务 ID |
| 模板版本和候选字段 | 业务模块 | 公文、论文、研究报告、报纸和自定义类型；字段需绑定原文证据 |
| 问题、人工决定、成果修订 | 业务模块 | 必核问题阻断确认；保留操作者、时间、原值、新值和依据 |
| 模型权重 | 麒麟宿主机 | 单独制品与只读挂载，不进入日常代码镜像；记录哈希和兼容组合 |

新业务契约从零定义。业务字段的证据引用至少包含业务文档 ID、MinerU 文档引用、解析修订/tier、定位器、页/块标识、可用 bbox 与**冻结的原文片段**；引用在服务端做权限检查，不能把 Doclib 内部路径直接交给浏览器或 Skill。P2 实测确认公开 locator 只有 doc/tier/page/block/char，**不含 parse_id**；重解析会创建新的解析 ID。因此 locator 只能用于当前文档导航，不能单独充当不可变证据；业务库必须保存解析 ID、当时片段与可用坐标的快照，已确认成果不因重解析静默改变。

业务身份契约（P3 实现前的设计决定）：每次用户创建的业务文档分配独立的不透明 ID；原文件 SHA-256 是内容身份，不能替代业务 ID，因为同一内容可以属于不同任务或权限域。业务文档保存不可变原文的存储键、原文件名、SHA-256、创建者和创建时间；绝对宿主路径只在服务端解析，不出现在前端/Skill 响应。解析修订另有业务修订 ID，引用 Doclib parse ID、实际 tier、源 SHA-256、生产者代码/模型版本和完成状态；重解析只新增修订，不覆盖旧修订。证据快照绑定业务文档和修订，保存 locator、可用页/块/bbox、原文片段及片段哈希；定位器失效时仍能展示冻结片段，但必须明确标记“无法回跳原文”，不得冒充仍可定位。确认成果引用特定证据快照，不随当前 Doclib 解析结果漂移。业务删除先撤销访问并按保留策略清理引用，不能把 `forget_path` 当作业务删除。该契约的表结构、事务和权限检查尚待 P3 实现与测试。

## 模块与运行角色

```text
浏览器 ─────┐
            ├── 业务 Web/API ── 业务库（任务、模板、复核、成果、审计）
自有 Skill ─┘        │
                     └── DoclibClient / 内部文档接口
                               │
                         MinerU Doclib 服务（唯一写入者）
                               │
                         MinerU 本地解析与 GPU 推理
                               │
                         只读模型目录 + 持久文档数据目录
```

`mineru.doclib` 已公开 `DoclibClient`、`DoclibInterface` 与类型化响应；优先在业务模块使用它。Doclib 具备实例所有权锁，不允许 Web 与 worker 各自直接写同一个 Doclib 数据目录。初版先验证 Client 的文档身份、parse/search/read/locator、删除和重启语义；仅针对公开接口不能覆盖的需求，集中扩展 MinerU 平台代码。

P2 发现 `ensure_parse` 接收的是 **worker 可访问的本地绝对路径**，不是文件字节上传。业务 API 应将原文件写入专用、不可变的共享上传目录，worker 以只读方式挂载同一目录并调用公开 `DoclibClient`；业务 API 不能向 Doclib 提交自己容器里独有的路径。共享目录与 Doclib 数据目录分别管理，不把原文件塞进代码镜像或模型目录。`mineru.business.documents.DoclibGateway` 当前先执行共享路径、格式档位、本地模式和文件哈希校验。

上传目录由 `ImmutableUploadStore` 执行限额流式写入、同步、完成后原子发布，按随机存储键保留每次上传的独立路径；同字节 SHA-256 可相同，但业务记录不合并。临时文件后缀不属于 Doclib 可解析格式，Doclib 不应扫描未完成上传。文件权限设为只读属于误操作防线，**不是防同 UID/管理员篡改的安全边界**；worker 必须只读挂载、上传目录只允许业务 API 写入，且 Doclib 提交前后仍校验原文哈希。业务 API 应将存储记录写入业务事务库；若事务失败，须有孤儿文件清理机制，不能把单独的文件发布视为完整业务提交。

逻辑上是**一套源码、一套产品**。物理上推荐业务 Web/API 与文档/GPU 工作进程分开运行，避免界面改动扰动显存中的模型；这通常产生两个代码镜像，但镜像数量不是交付目标。官方 WebUI 可保留作内部调试，不作为面向业务用户的主界面。官方 Router、独立 OpenAI-compatible VLM Server 不是单机初版必需服务。前端与自有 Skill 必须调用同一业务 API，禁止 Skill 直连原始 MinerU 结果并跳过复核状态。

## 核心流程

1. 上传原文，做格式/大小/安全校验与哈希计算，建立业务文档身份并交给 Doclib 入库。
2. 按当前部署能力选择解析策略：PDF/图片支持四档；Office/OpenDocument/EPUB/OFD/HTML/CSV 等原生文档使用 Flash。记录实际 tier、模型组合和源码版本。
3. 业务模板从解析块中生成字段候选与证据；质量规则生成必核/可选问题。机器结果一律标记为未确认。
4. 复核工作台联动原文、结构、字段、问题和定位器；人工修改可追溯。必核问题处理完才能确认结果。
5. 搜索和渐进式读取优先复用 Doclib；业务层在返回之前加权限与“原文/机器结果/人工确认”的状态语义。
6. 成果导出、前端与自有 Skill 读取统一的业务结果版本；渲染格式只按实际已验证的接口能力开放。

## 生产部署与更新

**完全断网是默认工况。** 联网准备环境生成精确版本的 x86_64 基础/运行镜像、离线依赖包、模型目录与 SHA-256 清单；经批准介质导入麒麟。生产运行禁用远程解析、远程 VLM、在线模型下载和在线依赖安装。模型下载针对目标 Torch + vLLM 配置，运行时设 `model.source=local` 和明确的 `model.base_dir`；启动前校验模型完备性，再用真实文档解析验证。具体 GPU/驱动/CUDA 兼容性以目标设备实测为准。

官方 Dockerfile 在构建时从包索引安装 MinerU 并下载权重，不用于最终交付。我们维护 fork 专用 Dockerfile：安装**本地 fork 源码**、使用离线依赖、把模型目录排除构建上下文。Mac 日常只传必要源码/锁文件；麒麟利用预置依赖本地构建受影响代码镜像。模型目录和文档/业务数据目录持久保存，不随重建覆盖。若上游更新了代码，合入确定提交并回归后重建受影响镜像；只有模型本身升级时才单独导入新模型制品。

## 安全和质量门槛

- 生产 API 必须鉴权；用户与 Skill 的读取、写入、确认分别授权并留审计。Doclib 仅对内部服务开放。
- 未确认的字段和 Agent 回答须明确标记；不允许从机器候选直接伪装成已确认成果。
- 模型、依赖、源码和配置分别锁定版本/哈希；发布清单描述可兼容组合，支持回退。
- 旧原型的合成黄金数据仅可作为需求示例；不代表新系统准确率。用公文、论文、研究报告、报纸的脱敏真实样本与人工标注测字段、结构、证据、复核成本与吞吐；手写、跨页表格、印章/水印专项验收。
- 麒麟断网启动、业务重启、Doclib 重启、模型缺失、解析失败、重复上传、重解析和恢复重试都要有自动化或现场测试记录。

## 尚待原型确认的设计点

1. DoclibClient 的持久文档身份、引用稳定性与删除语义是否足够支撑业务成果版本。
2. Doclib 的本地 socket/TCP 通道在两个容器之间如何安全暴露，单实例写入锁与重启恢复如何配合。
3. Office 等格式的原文预览、定位器几何信息与 PDF/图片是否一致；不能在未验证前承诺相同的 bbox 体验。
4. 业务库采用单机 SQLite 还是其他事务数据库，要由并发规模、备份/恢复和目标环境运维约束决定。
5. 第三方许可证与对外标识义务由项目方在上线前核对；此文档不是法律意见。
