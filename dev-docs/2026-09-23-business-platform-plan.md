# MinerU 4 业务平台开发与验证计划

状态：分阶段执行计划。基线见 [架构设计](2026-09-23-business-platform-design.md)；每阶段须有文档、代码、测试和验证记录，完成后停在阶段边界接受复核。所有开发在 fork 的 `master` 上进行，无旧 3.4/V1 迁移与兼容任务。

## 阶段划分

| 阶段 | 目标 | 主要产出 | 阶段完成证据 |
| --- | --- | --- | --- |
| P0 基线 | 架构、范围、源码与上游边界 | 本设计、计划、任务清单、进度记录 | 文档自洽；版本与工作树记录 |
| P1 离线交付底座 | 本地源码入镜像、模型外置、断网失败关闭 | fork 专用 Dockerfile、Compose、配置、发布清单工具 | 构建上下文不含模型；离线/模型缺失测试 |
| P2 Doclib 契约原型 | 验证公开客户端和文档库能力 | `mineru/business/documents/`、端到端契约测试 | 入库/解析/搜索/定位/重启/删除实测记录 |
| P3 业务领域与后端 | 新业务契约、模板、字段、问题、复核、审计 | `mineru/business/domain/`、`mineru/business/api/`、存储与测试 | 业务状态机及 API 自动化通过 |
| P4 业务前端 | 统一上传、文档库、证据与复核工作台 | `business-web/` 与 UI 测试 | 前端构建、关键流程和可访问性验证 |
| P5 自有 Skill | Agent 使用与前端一致的业务 API | `skills/business-documents/`、调用契约与状态测试 | Skill 不绕过复核状态的端到端测试 |
| P6 系统验收 | 真实样本、性能、隔离区与故障恢复 | 测试报告、发布清单、操作手册 | Mac 与麒麟分别验收，未知指标不填推测值 |

P1～P5 是开发阶段，不把一次能运行的演示冒充生产完成；P6 必须在目标麒麟硬件获得真实证据。若 P2 发现 Doclib 公开接口不足，先出具可复现缺口，再决定扩展接口还是修改内部实现，禁止提前散改核心。

执行例外（2026-09-23）：P1 的 Linux amd64 基础镜像、wheelhouse、真实模型与麒麟 GPU 断网验收依赖尚未取得的目标环境。P1 保持未完成、相关 `INF-*` 不虚报通过；与目标硬件无关的 P2 Doclib 契约原型先在 Mac 隔离目录推进。此例外不降低 P1/P6 最终验收门槛，也不允许将 Mac 结果当作生产结果。

后续并行范围（2026-09-23）：P2 已完成若干 Mac 契约原型，但跨容器、目标 GPU/模型和真实样本仍开放。为避免现场环境等待阻塞产品开发，允许在 Mac 上继续 P3 的领域/持久化/API 开发；其测试结果只证明该部分代码行为，不将 P1/P2 或 P3 整阶段标记为完成。P3 初期选用单机 SQLite 作为业务事务库，依据是当前明确的单台离线麒麟部署目标；并发容量、备份恢复及是否需要替换数据库须由现场验收决定。

## P0：基线与工作方式

- 固定 fork 当前提交与 MinerU 版本，保留官方 `upstream` 作为更新来源；只在 `master` 工作。
- 在 `dev-docs/` 保存架构、实施计划、特性清单、进度与阶段验证记录。
- 验证命令沿用用户确认的官方开发环境：`uv venv .venv`、`uv pip install -e '.[dev,test]'`、`.venv/bin/python -m pytest tests/unittest`；本地 CLI 解析样本做冒烟验证。具体命令在阶段记录中写出，不用旧系统命令冒充新系统结果。
- 仓库已有完整上游测试和许可证；任何删除先限定目标路径，检查是否为用户文件、上游资产或业务数据。

## P1：离线交付底座

已开始采用 `docker/business-api/Dockerfile`、`docker/worker/Dockerfile`、`docker/compose.business.yaml`、`scripts/offline_package.py` 与 `tests/business/test_offline_configuration.py`。API 与 worker 是两个代码镜像，共用外部模型目录由 worker 只读加载；两个镜像的启动/网络/离线性仍待目标机器验证。

- 从精确源码提交安装本地 fork，不从包索引安装浮动 `mineru>=4,<5`。
- 依赖基础层与业务代码层分离；构建上下文排除模型、文档库和用户文件。
- 目标配置指定容器内 `model.base_dir`，由麒麟宿主机只读挂载；`model.source=local`，模型缺失时明确失败，不自动在线下载。
- x86_64/NVIDIA 基础层、Python wheelhouse、前端依赖、模型目录、配置和 SHA-256 清单可独立离线导入；不能在生产 `docker build`/容器启动时访问公网。
- 测试“仅业务代码变化”“MinerU 源码变化”“模型变化”三种更新路径，记录实际需要重建/传输的制品。

## P2：Doclib 契约原型

拟新增 `mineru/business/documents/`、`tests/business/test_doclib_contract.py` 与实测记录 `dev-docs/evidence/`。尽量使用公开 `DoclibClient`/`DoclibInterface` 和类型，不复制 Doclib 的索引表。

- 使用独立测试目录完成文件入库、内容哈希/身份、Flash 与可用的高质量档位解析、搜索、按定位器读取和结果版本记录。
- 验证异常：同一文件重复上传、同名不同内容、重新解析、服务重启、删除/忘记、部分成功、模型不可用、无网络。
- 确认 Doclib 单实例写入所有权、容器间客户端通信和最小暴露面；若需要扩展，先写契约测试再修改核心。
- PDF/图片、DOCX/PPTX/XLSX 的可预览性与定位精度分别记录，不推断原生格式都具有 PDF bbox。

## P3：业务领域与后端

拟新增 `mineru/business/domain/`（文档/任务/解析修订/证据/问题/成果模型）、`mineru/business/services/`（模板、提取、质检、复核、导出）、`mineru/business/api/`（统一业务 API）、`mineru/business/store/`（事务存储）及 `tests/business/`。

- 所有业务 ID、状态、错误与结果契约从零定义；不对旧 StandardDocument V1、旧数据库或旧路由作兼容。
- 模板覆盖公文、论文、研究报告、报纸与自定义类型；保留模板版本快照。
- 字段候选必须有证据引用和来源类型；缺失、低置信、多候选、结构异常产生问题队列。
- 人工修订保留旧值/新值、来源和时间；必核问题未解决时确认接口拒绝；确认后的成果不可静默覆盖。系统不记录虚构的操作者身份。
- 不开发登录、用户、角色或令牌授权；开放业务 API 由物理隔离和内网部署限定可达范围。Doclib 内部 API 不作为外部业务 API。
- 持久任务可跨进程重启恢复；业务状态不依赖 V1 临时 job ID。

## P4：业务前端

已新增 `business-web/` 的零第三方依赖静态模块与生产构建，生成带逐文件 SHA-256 的 `dist/`，同源托管在业务 Web/API 镜像；这样麒麟离线构建无需前端包索引。上传/文档任务/原文入口、候选—证据—复核—确认成果、文档级索引检索、历史解析渐进读取、原生块树、块级候选与显式证据冻结、模板管理、质量统计和全局审计已通过相应 Mac 浏览器流程。字段与原文双向联动等 P4 功能及四类真实样本端到端仍缺；合成浏览器测试不代表生产验收。官方 Gradio WebUI 继续作为内部解析调试工具，不承载业务主流程。

- 导航：文档/任务、解析工作台、复核、成果、模板/运营；明确展示解析档位与实际运行时不同。
- 上传界面按文件类型及服务能力约束档位；异步状态、失败、重试、批量异常逐个反馈。
- 原文/结构/字段/问题联动；证据可跳回页/块；定位不可用时给出明确说明而非伪造坐标。
- 草稿与已确认成果严格区分；人工修改和版本记录可查。
- UI 构建、组件测试和浏览器关键流程验收均留证据。

## P5：自有 Skill

已新增 `skills/business-documents/` 的自有 Skill 元信息和零第三方依赖业务 API 客户端，覆盖提交、任务进度、最新修订/提取概览、机器候选/问题、冻结证据、已确认成果、业务范围检索及修订绑定的定位器续读。冻结证据可返回同源业务 Web 深链，供用户在同一业务界面核验。它只调用 P3 的开放业务 API；结构树和页块级检索证据仍待 API 与 Web 同步补齐，不能回退到 Doclib 或官方 Skill 冒充完成。

- 对未复核输出显式标记状态；Skill 默认不自动执行人工确认，这属于流程规则而非权限认证。
- Skill 不直连官方 MinerU Skill、V1 原始解析 API、Doclib 内部接口或文件路径。
- 包含端到端示例、输入限制、引用格式、错误语义和状态测试；生产不含远程上传能力。

## P6：测试、现场验收与发布

- 单元/契约/集成：官方上游测试保持可运行，新增业务测试覆盖状态机、证据、Doclib 适配、格式/档位和离线配置。
- 真实业务样本：四类文档各有脱敏原文与人工标注；字段准确率、结构质量、证据命中率、复核工作量如实报告。手写、跨页表格、印章/水印专项。
- 四类样本的只读计分输入、原文哈希核验、业务身份校验和脱敏指标报告格式见 [real-sample-acceptance.md](real-sample-acceptance.md)。工具/合成契约通过不等于真实样本执行；P6 `QA-007`–`QA-022` 在样本与标注到位并实测前仍不标完成。
- 故障：模型缺失/损坏、GPU 不可用、磁盘满、Doclib 重启、工作进程中断、重复任务、恶意或超限文件、断网启动。
- 麒麟现场：确认系统版本、GPU/驱动/CUDA、推理引擎、显存和吞吐；在无公网条件下导入、构建/启动、备份恢复和回滚。
- 发布清单记录 MinerU 源码提交、业务提交、离线依赖/镜像哈希、模型哈希、配置、测试报告和已知限制。

## 上游更新规程

锁定每次上游版本；先阅读变更、合入 fork、解决冲突，运行上游和业务回归。模型变更与代码变更分别作为制品，但按兼容矩阵共同发布。不能将“合并成功”当作“业务可用”；解析结果、定位器、模板抽取、Skill 契约与离线启动均需验证。

## 当前尚缺的现场信息

麒麟发行版及版本、NVIDIA GPU/驱动与显存、批准的离线介质流程、真实脱敏样本与人工标注、业务 API 所在内网的可达范围和备份保留期。它们不阻止 P1/P2 在 Mac 上开发，但会影响 P6 的生产验收结论。
