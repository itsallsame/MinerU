# 复核证据列表异步恢复（Mac，2026-09-24）

## 问题与边界

提取运行由 `queued` 转为 `done` 后，Web 会重新读取当前解析修订的冻结证据。该请求失败时，原实现仅显示错误；复核页继续以空证据列表渲染，可能误导用户认为没有证据或字段关联，且无原地重试入口。此处仅处理 Web 异步展示与恢复，不改变证据、提取或权限模型；系统仍无用户、登录和权限管理。

## 修复

- 证据刷新失败时保持明确的“证据及字段关联状态未知”状态，隐藏依赖该列表的复核内容，避免将读取失败解释为空结果。
- 提供“重试读取证据列表”；重复失败仍可重试，成功后恢复完整复核页。切换文档或解析修订时清理失败状态；延迟返回不得污染新上下文。
- `loadRun` 不会在未重读证据时抹掉失败状态。

## 验证

先扩展 `review_recovery_browser.py`，模拟提取从排队转完成且证据请求返回 503；修复前 Chromium 在查找重试按钮时超时。修复后验证失败提示、不展示伪空字段、首次重试仍失败、再次重试成功。`pnpm test` 为 11/11，`pnpm build` 生成 8 个离线 Web 资产，`pnpm test:browser` 为 19/19。
