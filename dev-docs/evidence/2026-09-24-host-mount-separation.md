# 离线部署宿主目录隔离检查

日期：2026-09-24。分支：`master`。环境：macOS；未在麒麟 x86_64/NVIDIA 现场运行。

发现：worker 模型目录的 `:ro` 挂载只限制 worker。若操作者误把业务上传目录或业务/Doclib 数据目录设成模型目录本身、父目录或子目录，另一个可写挂载仍可修改权重。原运行预检只核对容器内目的路径及单个挂载读写标记，未检查宿主源目录关系。

措施：增加启动前 `scripts.verify_host_layout`，要求四个目录和模型清单已存在，拒绝符号链接挂载根、目录相同/祖先/后代关系，以及清单位于任一挂载目录中。运行预检再以 Docker inspect 返回的实际宿主源路径核对一次；符号链接别名通过 `resolve()` 识别。该检查不修改任何业务或模型文件。

验证：定向 35 项测试通过，包含正常目录、同目录、祖先/子目录、符号链接别名、清单落入上传目录、CLI 缺失目录及运行态错误挂载。完整 `tests/business` 在允许本机 Unix/TCP 测试 socket 后 166 项通过、2 个已有依赖弃用警告；首次普通沙箱运行因不允许本机监听出现 19 个 setup error 和 1 个失败，授权重跑原命令通过。Ruff 与 `git diff --check` 通过。Mac 测试只证明校验逻辑；麒麟实际路径、Docker 挂载和 GPU 仍需现场验收。回滚仅撤销预检代码与文档，不触碰模型或业务数据。
