# 离线 worker 拒绝远程解析意图

日期：2026-09-25。范围：Mac 合成 SQLite、Doclib API 与业务测试；没有麒麟 x86_64＋NVIDIA 现场运行或物理断网证据。

## 缺口

前一轮让离线 worker 的有效远程 URL 为空，并阻止远程健康探测；但旧 Doclib 数据库仍可能有 `privacy=remote` 的待执行任务或远程解析规则，也可能收到显式 `remote=true` 请求。仅依赖空 URL 会把意图推迟到解析时失败，且旧流程可能尝试回退到本地，不利于准确解释任务结果。

## 行为

- 离线开关开启时，新的显式远程解析请求在读取/入库原件前返回明确的 `remote_disabled`（HTTP 400）；远程解析规则也不能新增。
- 旧库中已排队的远程任务在 worker 执行时标为 `failed / remote_disabled`，不读取原件、不访问远程解析服务，也不伪装成一次成功的本地解析。历史记录保留供核对；非离线安装原有远程能力不变。
- 同一个错误码用于配置 API 的远程 URL 写入拒绝，属于已登记的请求错误。业务网关继续只提交 `remote=false`，Doclib 仍位于无宿主端口的内部网络。

## 验证

新增回归先分别失败于“原件不存在优先报错”“旧任务缺少离线失败闸门”和“配置 API 使用泛化错误码”，实施后通过。无覆盖率定向 pytest：离线路径 3 通过；现有非离线远程与错误分类回归 23 通过。完整业务回归 381 通过、2 跳过；核心改动 Ruff、`git diff --check`、功能清单 JSON 校验通过。既有大型 Doclib 单测文件不以全文件 Ruff 无告警作为本轮结论。

这些测试证明程序边界，不证明目标机的 Docker 网络、模型加载、GPU 解析或真实文件质量。INF-012 仍保持未完成。
