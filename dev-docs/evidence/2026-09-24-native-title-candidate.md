# 原生标题候选的来源约束（2026-09-24）

范围：BE-032 的一部分。当前系统是开放式单实例：没有登录、用户、角色、权限或租户管理；人工确认仅改变内容复核状态，Web 与自有 Skill 使用同一业务 API。

候选提取先在固定业务修订和冻结模板版本的所有解析页寻找显式“标题：值”。若不存在，且模板有 `title` 文本字段、页 1 属于该修订，则读取对应历史 parse ID 的原生结构，只考虑第一页顶层 `doc_title` 块。核对文档哈希、短 ID、档位、页码、块路径和定位器，读取完整块内容，并经同一历史来源冻结证据后才写入 `native_doc_title` 候选。短预览不作候选值或证据；多行、过长、图片语法内容不猜测。候选仍是 `machine_unconfirmed`，不生成未经标定的置信分数；报纸 `article_title` 不套用单一文档标题规则。

业务 SQLite schema 升至 11，新增候选方法约束。旧 schema 10 开发库不隐式迁移；备份工具也只接受当前 schema 11。用户已明确旧原型无需代码、数据或兼容迁移，但删除旧数据仍须确认精确目标。模型权重继续外置在宿主目录，业务代码改动不要求把模型打进镜像。

验证：`tests/business/test_field_extraction.py`、`test_state_backup.py`、`test_business_store.py` 定向 38 项通过；完整 Mac 业务套件 302 项通过、2 项按现有条件跳过，2 个依赖警告。新增旧 schema 10 拒绝用例在完整套件启动后补入，随后单独补跑。Ruff lint 与 `git diff --check` 通过。当前没有四类人工标注真实样本、隔离麒麟 x86_64/NVIDIA、真实模型质量和离线回退证据，因此 BE-032、P6 与总 Goal 继续保持未完成。

续测：新增真实本地 Doclib HTML `<h1>` → 业务上传/解析 → 自动入队提取 → 冻结证据链路。首次运行发现原生标题块在页标记和 Markdown 标题之间还有 `<a id="html-…"></a>` 锚点，导致单行约束漏提；已限定为只跳过解析器产生的十六进制 HTML 锚点，不忽略任意锚点或多行正文。修正后真实链路与提取定向测试合计 17 项通过，完整 Mac 业务回归 305 项通过、2 项按现有条件跳过、2 个依赖警告；Ruff lint、JSON 和 diff 检查通过。此测试不需要模型权重，仍不能代表 PDF/图片的模型标题质量。
