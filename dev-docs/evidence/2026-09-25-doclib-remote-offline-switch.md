# 离线部署禁用 Doclib 远程解析

日期：2026-09-25。范围：Mac 上的配置/模拟部署回归；尚未在物理隔离的麒麟 x86_64＋NVIDIA 环境构建与启动。

## 发现

Doclib 通用默认值 `parse_server.remote.url` 指向官方服务。此前生产 Compose 虽设置模型本地源、离线环境变量和内部 Docker 网络，却没有覆盖该值；Doclib 的后台健康循环仍会尝试探测远程 URL，运行态预检则因远程 URL 非空而拒绝。这意味着“只使用本地解析”不能仅凭模型环境变量或隔离网络推断。

## 部署约束与实现

- 生产 worker 的 Dockerfile 与 Compose 显式设置 `MINERU_DOCLIB_REMOTE_DISABLED=1`；离线启动预检和运行态预检均要求该值，且补齐 `HF_DATASETS_OFFLINE=1` 的启动预检。
- Doclib 配置服务在该开关下将有效远程 URL 固定为空，即使 SQLite 中留有旧的远程 URL；API 读取和状态读取一致。试图在此模式下写入远程 URL 会被拒绝，不静默改写持久配置。非离线部署沿用官方默认行为。
- 空远程 URL 的健康检查返回 `parse_server_disabled`，不建立 HTTP 客户端或发出探测请求；业务网关继续强制本地提交。Compose 内部网络仍是独立的隔离边界。

## 验证与边界

定向测试覆盖持久远程 URL 的有效覆盖与拒写、空 URL 不探测、Doclib 状态/API、启动与运行态缺少开关时失败；最后一次无覆盖率的 Mac 定向 pytest 为 60 通过、1 跳过。完整业务回归首次受沙箱 Unix socket／端口绑定限制，允许本地绑定后重跑 379 通过、2 跳过。该次业务回归与另一个 pytest 进程并行造成 coverage 数据文件争用警告；测试断言均通过，覆盖率报告不作为本次证据。`git diff --check`、功能清单 JSON、核心源码及业务测试 Ruff 检查通过；两个既有大型 Doclib 单测文件的全文件 Ruff 检查有本轮之前就存在的注解/行长告警，本轮新增行已单独核对。

这只是离线配置和程序行为的本机证据；不能证明物理断网、目标机 GPU 模型加载或真实文档质量。INF-012 保持未完成，目标机仍须核对实际运行状态、网络与端到端解析。
