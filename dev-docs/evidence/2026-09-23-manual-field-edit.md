# 人工字段修改表单闭环

日期：2026-09-23。范围：P4 FE-032。

业务 Web 的字段卡允许填写修订值、选择冻结原文证据，并为人工改值填写原因；点击“保存复核决定”调用开放业务 API，写入新决定。首次接受机器候选与后续人工修订是两条不同的决定记录，不直接改写旧决定或已经确认的成果。提交后工作台重新读取最新决定；新决定使下一版成果可以确认，旧版本保持不可变。无登录、用户或审批权限；`source=web` 仅表示入口。

验证：`cd business-web && pnpm test && pnpm build` 为 11 个单测通过、8 个离线资源。Playwright `review_browser.py` 在真实前端 bundle、模拟业务 API 下，用表单填写“规范化标题”、证据和原因，按 Enter 提交，检查 POST 内容、人工修订状态、焦点连续性及再次确认入口；整个候选接受—问题解决—v1 成果—人工改值流程通过。后端 `.venv/bin/python -m pytest tests/business/test_review_results.py -q` 为 9 passed、2 个已有依赖弃用警告，覆盖人工修订原因约束及旧成果不可变。

边界：浏览器数据为合成记录；尚未用四类真实文档或麒麟 NVIDIA 目标机验证字段质量与操作体验。
