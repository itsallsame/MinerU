# 冻结证据内容完整性门槛（2026-09-24）

范围：P3 `BE-040` 的候选—证据关联加强。证据创建时已保存原文片段与 SHA-256，但历史读取和后续复核只使用片段本身，未对保存的哈希再次核对。若 SQLite 中的片段单独损坏，界面有机会把失真内容作为“冻结证据”展示。

现在业务存储在 `get_evidence`、`list_evidence`、候选写入、字段复核决定和成果确认前核对片段哈希。核对不一致时，证据详情与列表业务 API 返回 409 且不包含损坏片段；写入候选/决定/成果则拒绝事务。Doclib 当前定位核验仍使用原有 `current_match/changed/unavailable` 契约，不能用实时内容替代冻结片段。Web 与自有 Skill 共用这些业务 API；系统不因此增加登录、用户、角色或权限管理。

验证：用测试数据库仅修改片段、不修改哈希，检查详情/列表不泄露损坏内容，候选、决定和成果确认不能继续；未损坏文档修订仍可读取。还验证了**同一文档的另一次解析修订**即使定位器与片段文字相同，也不能把其证据挂到本次提取运行。定向证据/提取/复核 52 项通过；最终 Mac 完整业务回归 339 通过、2 跳过、2 个第三方依赖警告，Ruff lint、feature-list JSON 与 diff 检查通过。没有 schema 或模型目录变化。

限制：SHA-256 只能检测内容与原保存哈希不一致，不能抵御能同时修改片段与哈希、证据关系及确认记录的数据库管理员；真正防篡改需独立签名/外部见证及密钥管理，当前没有作出该承诺。四类脱敏真实样本、物理隔离麒麟 x86_64+NVIDIA 和现场恢复仍待验收。
