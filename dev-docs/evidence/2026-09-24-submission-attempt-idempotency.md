# 强制重试的提交世代与取消竞态

日期：2026-09-24。范围：开放业务 API → Doclib 提交/释放协议；不增加用户、登录、角色或权限管理。`consumer_key` 仅是工作意图与幂等标识，不是身份凭据。

## 问题与裁决

业务解析失败后会以 `force` 再提交。原协议只以稳定消费意图键登记批次；若 Doclib 已建批次但响应丢失，原批次又在重试前完成，同一次强制重试可能再次建批次。业务旧轮询也可能在新提交之后把任务写回失败或完成。因此仅靠消费意图键、业务状态或短期缓存都不能证明一次重试只提交一次。

业务 schema 10 持久化任务的 `submission_attempt` 与 `submission_force`：初次提交用世代 1；未知提交结果重放相同世代和 force；只有已确认的解析失败、覆盖不足或无效批次触发新世代并启用 force。Doclib schema 5 在一个写事务中保存每个 `(consumer_key, attempt)` 的请求指纹和首次响应。相同请求重放保存的响应，不因批次状态变化而重新排队；同世代不同请求、世代跳号、意图已释放、版本化意图再用无世代请求均拒绝。取消墓碑对所有世代生效。业务提交结果、失败轮询与完成修订均检查当前世代；迟到的旧请求只能读到当前任务状态，不能覆盖它。

业务 schema 9 的本地开发库不隐式迁移为 schema 10；Doclib v4→v5 使用正式迁移。离线备份校验与部署说明已更新为当前版本。旧证据中的 schema 9 为当时版本记录，不能作为当前部署要求。

## 已验证范围

- Doclib 单元测试：同世代 force 在原批次结束后、服务重启后仍重放原响应；新世代创建新批次；参数冲突、跳号、无世代和取消后提交被拒；两实例同时提交同世代只有一个批次。迁移测试验证 v4→v5 保留释放墓碑。
- 业务测试：两个工作流实例并发重试共用世代；丢失响应后仍以原 force 请求恢复；旧失败/完成轮询不能覆盖新世代；schema 9 被显式拒绝；备份要求 schema 10。
- 真实 Doclib 公共 SDK 路由：提交世代、已完成后的重放、新世代与释放结果联调通过。

最终验证命令：`.venv/bin/python -m pytest -q tests/business` 为 264 passed / 1 skipped；`.venv/bin/python -m pytest -q tests/unittest` 为 2832 passed / 4 skipped。真实 SDK 提交世代与取消的定向联调 2 passed。Ruff、JSON 格式和 `git diff --check` 通过。第一次无本机 socket 权限的完整业务测试在 Doclib Unix/TCP 绑定时失败；获得本机测试权限重跑后全部通过，不把沙箱错误算作业务回归结果。

尚未验证隔离麒麟 x86_64＋NVIDIA、真实模型质量、四类标注样本、目标机重启/回退；也不承诺运行中的 GPU 任务可被抢占或两个 SQLite 库之间有原子事务。目标发布验收保持独立门槛。
