# P3 持久异步字段提取队列（2026-09-23）

## 实现

- 原同步 HTTP 提取改为 `202 queued`；业务 API lifespan 启动/停止后台提取线程。线程使用独立 DoclibClient，不加载模型或 GPU。
- SQLite schema 6 的运行状态为 `queued/running/done/failed`。同一解析修订同时最多一个排队或运行中的提取，重复提交返回同一运行 ID。
- 事务认领附随机 claim token 与 3 分钟租约；逐页和两次 Doclib 读取之间续租。候选写入、完成、失败都校验令牌与未过期租约。超时重领同一运行时清除上一尝试的未确认候选，旧 worker 无法写入；连续三次租约耗尽则显式失败。
- 运行状态和候选/问题持久化于业务数据库；API 不暴露 claim token、租约或 Doclib parse ID，失败/未完成运行不返回部分候选。服务重启无需丢弃排队运行。

## 验证

- 定向测试覆盖幂等提交、跨 store 实例重启认领、租约过期重领、旧令牌拒写、部分候选清理、最大次数失败，以及 FastAPI lifespan 后台完成。
- Mac 完整 `tests/business`：**84 passed、2 warnings**（54.33 秒，允许本地 Unix/TCP socket）；Ruff 检查通过。
