# 离线发布绑定 Web 源码与静态产物

日期：2026-09-25。范围：Mac 上的确定性 Web 构建、发布清单/导入校验合成回归；没有在麒麟目标机执行 Docker build 或导入。

## 发现与处理

此前发布清单记录了 `business-web/dist/asset-manifest.json` 及资源哈希、业务镜像中的 manifest 标签，却未核对 `dist` 是否来自清单所记 Git 提交中的 `business-web/src`。因此一个内部一致但过期的页面，理论上仍可随新版业务 API 制作发布记录。新增两个回归断言先失败：过期页面没有阻止发布清单生成，也没有阻止导入报告生成。

发布清单 CLI 现在在确认 Git 工作树干净后，从该仓库根目录读取 `business-web/src`，要求每个 HTML/CSS/JS 源文件与 `dist` 清单的文件集合和 SHA-256 一致。导入校验 CLI 现在**必须**提供 `--source-tree`，先核对它是所选提交且工作树干净，再核对传入的 Web `dist` 与该源码树逐文件一致；失败不写成功报告。`verify_release()` 的纯制品核验仍可单独用于单元测试，但不能绕过 CLI 的发布验收门槛。该约束适用于首次交付和代码单独更新，避免传输了新源码却继续发布旧页面。
