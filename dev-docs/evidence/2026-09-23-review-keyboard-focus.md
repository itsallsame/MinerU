# 复核工作台键盘焦点连续性

日期：2026-09-23。范围：FE-046 的关键写入路径增量，尚非完整可访问性验收。

发现：复核操作会重绘工作台。键盘激活“接受候选”“标记已解决”或“确认并生成不可变成果版本”后，原按钮被移除，焦点可能丢失到页面根部，用户无法顺着原上下文继续操作。

处理：写入开始和完成时将焦点恢复到相应字段卡、问题卡或最新成果卡；这些目标可程序化聚焦并显示轮廓。焦点恢复受当前文档/运行上下文约束，用户切到另一文档后旧写入不会夺回焦点。未新增登录、用户、角色或权限逻辑。

验证：`cd business-web && pnpm test && pnpm build` 为 10 个单测通过、8 个离线资源；Playwright `review_browser.py` 用 Enter 键实际触发上述三项写入，并检查新卡片是当前焦点且轮廓可见，完整复核/下载流程通过。`keyboard_focus_browser.py` 文档列表焦点通过；`review_race_browser.py` 延迟写入 A→B 上下文隔离通过。浏览器测试使用模拟业务 API，不是麒麟环境或真实文档验收。

余项：仍需对整个复核工作台逐项 Tab/Shift+Tab、禁用状态、错误恢复与屏幕阅读器朗读做完整检查，FE-046 保持未完成。
