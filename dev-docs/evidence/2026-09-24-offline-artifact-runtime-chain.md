# 离线制品校验与运行态预检串联（Mac，2026-09-24）

## 缺口

部署手册要求先校验导入镜像、wheelhouse、Web 和模型，再验收运行态；此前 `verify_business_runtime` 并不读取制品校验报告，可以跳过第一道门槛。`verify_offline_release` 的成功报告使用替换写入，会覆盖同名旧报告，削弱发布证据可追溯性。

## 修正

- 制品校验报告写入所选 `release.json` 的逐字节 SHA-256，并采用原子、只创建一次的发布方式；旧报告不能被同名新报告覆盖。
- 运行态预检新增必填 `--artifact-report`，在接触 Docker 前核对报告为成功状态、所选发布清单哈希、源码提交、平台、基础/worker/业务镜像 ID、模型清单哈希及已校验文件数量。失败或旧版报告拒绝进入运行态检查。
- 运行态报告记录已核对的制品报告 SHA-256，同样只允许新建，形成发布清单 → 制品校验 → 运行态预检的证据链。命令和独立版本目录约束已写入 `dev-docs/offline-deployment.md`。

## 验证与限制

定向验证 39/39；完整业务测试在具备本地套接字权限的 Mac 环境为 191 passed、1 skipped（另有 2 条依赖弃用警告）。首次受限运行的 Doclib 套接字绑定被沙箱拒绝，非功能回归。Ruff 与差异空白检查通过。

当前 Mac 仅有 `mineru:4.0.2` 的 arm64 镜像，无可用的 Linux amd64 NVIDIA 基础镜像；测试使用模拟 Docker inspect，不能据此标记麒麟/NVIDIA、物理断网、模型加载或真实样本验收完成。报告本身须保存在受控介质；哈希串联不能替代现场制品重新核验或防篡改签名。
