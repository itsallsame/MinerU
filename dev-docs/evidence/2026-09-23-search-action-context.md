# 检索结果操作的文档上下文隔离

状态：Mac 浏览器合成数据验证通过；FE-047 仍未整体完成，真实样本和麒麟/NVIDIA 现场验证未做。

从块级检索结果点击“冻结此块原文”时，业务 API 可能在用户已切换到另一文档后才返回。此前成功回调会再次选择原文档，覆盖用户当前导航。现在记录操作发起时的文档选择序号和检索序号：服务端已经接受的冻结仍视为成功，但过时回调不改变当前文档；仍在页面上的原检索结果提示“原文已冻结到原解析修订；当前文档保持不变”。过时失败也不向新上下文插入错误。对“打开并读取此块”，在文档选择异步完成后再核对选择序号与文档 ID，旧操作不读取到新工作台。

验证：`cd business-web && pnpm test && pnpm build` 为 10/10、8 个离线资源。使用本地静态服务器与模拟业务 API 的 Playwright：`search_write_race_browser.py` 延迟冻结和修订读取，期间切换至第二份文档，断言冻结请求仍发给原修订、界面留在新文档，旧块读取不发出内容请求。既有 `review_race_browser.py` 和 `async_panels_recovery_browser.py` 同样通过。上述验证不代表真实 Doclib、模型或目标机运行。

剩余：还须覆盖问题处理、成果确认、字段生成及其他写操作在切换文档/修订时的边界；不能将当前几个场景替代 FE-047 整体验收。
