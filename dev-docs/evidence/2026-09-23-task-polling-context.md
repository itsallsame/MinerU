# 任务状态轮询与当前视图隔离

日期：2026-09-23。范围：P4 FE-013“任务进度轮询”。

业务 Web 每 4 秒检查当前列表中待提交/解析中的任务。任务由 `submitted` 变为 `done` 时刷新列表；若用户仍停留在同一文档，重新读取其解析修订。失败状态及 `error_code` 变化也触发刷新。轮询期间切换筛选/页码会使旧请求失效；切换文档后旧轮询不会重新选择文档或覆盖当前工作台，过期失败也不显示错误。轮询不提交解析、不更改模型，也不引入用户或权限系统。

验证：`cd business-web && pnpm test && pnpm build`，10 个单测通过并生成 8 个离线资源。Playwright `task_poll_race_browser.py` 在真实离线 Web bundle、模拟业务 API 下验证：选中文档完成时修订重新读取；任务完成刷新列表；轮询期间 A→B 选择不发生旧重选；更换状态筛选后旧 503 不污染当前错误区。原有 `upload_retry_race_browser.py` 与 `recovery_browser.py` 回归通过。`git diff --check` 与新测试 Ruff 检查通过。

边界：API 只提供任务状态与错误代码，没有页级百分比，因此界面显示离散状态而不伪造进度百分比。模拟时序验证不代替真实 Doclib/模型运行、四类样本和麒麟 NVIDIA 完全离线验收。
