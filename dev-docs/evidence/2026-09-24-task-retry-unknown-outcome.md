# 任务重试响应丢失时的前端状态核对

范围：P4 FE-047 的一条竞态。业务平台是开放系统，无登录、用户、角色或权限层；Web 和自有 Skill 仍走同一业务 API。后端此前已有任务提交世代及 Doclib 首次响应持久重放，前端不能把网络断开、5xx 或成功响应损坏直接解释为“任务重试失败”。

现在“重新提交任务”出现上述未知结果时，Web 先对同一任务 ID 执行只读 GET，再根据最新状态刷新文档列表；不自动再次 POST。如果连任务 GET 也失败，原按钮切换为“核对任务状态”，其后点击只进行 GET，页面明确提示结果未确认、不要重复提交。明确的非未知错误仍显示未受理。文档/筛选已切换时，迟到响应不会把旧错误贴到新选择。

验证：`cd business-web && pnpm test && pnpm build`，Node 12 项通过、生成 8 个离线静态制品；`python3 scripts/run_browser_tests.py` 的 24 个离线 Chromium 回归全部通过。新增浏览器用例模拟 POST 已被服务受理但回给浏览器 503，以及 POST 和后续 GET 都暂不可用，再核对按钮恢复；两个分支均断言不会暗中发第二次 POST。测试使用合成 API，没有真实网络故障、麒麟浏览器或 GPU 模型结论。

边界：一次成功的 GET 是请求时刻的任务状态快照，不证明之前的 POST 在所有并发路径下最终完成。后续若状态仍为失败，用户可以依据最新状态选择再次提交；后端同世代幂等协议仍是避免重复排队的最终保护。本项不使 FE-047 或整个 P4 阶段自动完成。
