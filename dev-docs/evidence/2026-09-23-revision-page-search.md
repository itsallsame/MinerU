# 历史解析修订的逐页检索（Mac）

日期：2026-09-23。范围：MinerU 4.0.6 fork 的业务 API、Web、自有 `business-documents` Skill；开放系统，无用户或权限模型。

## 契约与边界

文档级 `/api/business/search` 仍返回当前 Doclib 索引的未确认预览。新增 `/api/business/revisions/{id}/search` 只在指定业务修订保存的历史批次上逐页搜索，按页定位器返回机器文本片段；每次最多 25 页，`next_page` 用于续扫。页面被截断、历史批次不可读或身份核对失败时返回错误，不把不完整读取伪装成无命中。Web 从文档级命中进入“查找原文页→打开并读取此页”；Skill 使用同源业务 API 的 `search-pages` 命令，均不直连 Doclib。

命中状态为 `historical_parse_unconfirmed`，不是冻结证据、人工确认事实或块级精确引用。每页目前只返回首个命中；一段文本可能有多个命中尚未列举。Agent 给出最终引用仍需冻结证据 ID 或确认成果的证据。不能据一页窗口没有命中就断言整个文档没有相关内容。

## 验证

- 真实 Doclib + 业务 FastAPI：仓库 13 页 PDF 的历史修订以 `afforestation` 搜索得到页定位器；路径与内部 parse ID 不外泄。
- 模拟两个历史批次覆盖 27 页：第一个 25 页窗口无命中并返回 `next_page=26`，第二窗口在第 26 页命中且使用正确批次；非法页被拒绝，截断页返回 409。
- Skill 通过真实 FastAPI ASGI 适配测试 `search-pages`；Skill 结构校验通过。
- 全量业务测试 108 通过（2 条依赖弃用警告）；前端测试 7 通过、离线构建 7 个资产；Playwright 在实际构建包上验证文档预览→历史页命中→读取续段通过；Ruff 与 diff 检查通过。
