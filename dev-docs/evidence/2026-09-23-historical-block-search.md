# 历史块级候选搜索与显式证据冻结（Mac）

日期：2026-09-23。范围：MinerU 4.0.6 fork 的 Doclib 公共接口、开放业务 API、Web 与自有 Skill。

## 实现契约

- 文档级当前索引只负责发现业务文档，不充当页块证据。指定业务修订后，Doclib 只读取对应历史 parse 批次的持久 Middle JSON，搜索顶层模型块及其子块文字，返回顶层块定位器、页码、块号、可用 bbox 和至多 200 字符片段；图片载荷、URL、sidecar 路径不作为搜索文本。
- 业务层按修订保存的逐页 parse ID 调用并校验 SHA-256、short ID、tier、页码、块号与定位器。每次最多扫描 25 页，以 `next_page` 续扫。超出 Doclib 的页面/节点/文本/命中上限或业务总命中上限时失败，不把局部结果伪称完整召回；响应不含 parse ID/宿主路径。
- Web 将命中标为“机器解析候选，未人工确认”，可打开历史块。只有用户点击“冻结此块原文”才调用原有证据写入 API，服务端重新按历史 parse ID 读取并冻结内容；冻结证据仍不等于人工确认的字段。Skill `search-blocks` 与 Web 共用业务 API，不提供自动冻结或确认。

## 验证

- 真实 HTML 本地解析后强制重解析并只改动新批次持久结果：旧批次搜到旧标题，新批次搜不到；业务修订仍命中旧批次，按命中块定位器冻结的快照包含旧文本、不含新文本。
- 真实 Doclib 读取合法嵌套 list→text Middle JSON，子块文字命中并归到顶层块定位器。
- Mock 契约覆盖历史分批路由、业务 API 无内部 ID/路径、伪造块号/定位器拒绝；Skill 通过真实 FastAPI ASGI 适配器查询同一块级接口。
- Playwright 对实际离线 Web bundle 验证候选显示、历史块读取和显式冻结按钮；Web 9 项测试与 8 资产构建通过。业务回归 113 项通过（2 条依赖弃用警告），相关 Doclib 测试 41 项通过，Ruff 与 Skill 快速校验通过。并发 pytest 曾造成 `.coverage` 报表竞争，随后单独重跑相关 Doclib 41 项通过；该并发告警不作为覆盖率证据。

## 未验收

本次是 Mac 开发环境验证，不是四类人工标注业务样本的质量验收，也不是物理隔离的麒麟 x86_64 + NVIDIA 目标机验收。查询上限会以显式错误提示用户缩小范围，不承诺全库无限量召回。
