# 复核不可变写入后的读取恢复（2026-09-24）

## 范围

复核页有两种不可变写入：确认成果版本，以及从历史解析位置冻结原文证据。两者原先都把成功 POST 与后续 GET 串成一次操作；若 POST 已返回 201、GET 却返回 503，页面只显示读取错误或继续开放采集，容易误导操作者重复写入。

## 改动

- 成果确认以 POST 返回的版本号为准。随后运行详情、成果列表等读取失败时，显示“成果 vN 已确认，但复核数据读取失败”，并沿用只读的“重试读取提取运行”；不再把已确认的成果说成写入失败。
- 证据冻结以 POST 返回的证据对象为准，立即纳入本地列表并清除上一条证据的核验视图。后续列表读取失败时显示“证据已冻结”，进入列表未知状态，提供只读重试。若核验详情读取失败，也明确区分冻结成功与核验失败。
- 读取列表短暂未包含新证据时保留 POST 返回的证据，避免刚写入的对象在视图中消失。
- 仍是无用户、无登录、无权限管理的开放系统。

## 验证及限制

- `business-web/tests/review_browser.py` 模拟成果 POST 201 后成果列表 GET 503：修复前等待成功确认文案超时，修复后显示版本 v2 已确认；只读重试恢复 v2，确认写入数不增加。
- 同一浏览器回归模拟证据 POST 201 后证据列表 GET 503：显示已冻结及列表重试，证据写入数保持 1。
- `cd business-web && pnpm test && pnpm build && pnpm test:browser`：11 项 Node 测试、离线构建、19 项 Chromium 回归通过。

这些是 Mac 上的合成 API 验证；不能替代真实样本、物理隔离麒麟/NVIDIA 机器的验收。FE-047 尚有其他异步边界，仍不标完成。
