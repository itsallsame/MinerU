# 原件重试后的键盘焦点连续性

日期：2026-09-25。范围：开放业务 Web 的原件可用性核验与预览，不涉及模型或权限系统。

原有页面在用户键盘触发“重试核验原件”后，立即重建详情区域，旧按钮被移除；核验成功后再重建一次。Playwright 新断言先在旧代码上复现失败：PDF 原件恢复可用、链接出现，但焦点不在新链接上，键盘用户失去操作位置。

修正后，重试会把焦点移到带可见轮廓的“正在核验”状态；仅当用户仍停在该状态时，核验结束才把焦点交给新原文链接或新的重试按钮。用户在等待期间主动移走焦点时，不再抢回。详情因后台文档列表刷新而重建时，也按原件状态控件的语义保留焦点。图片核验成功后若浏览器解码失败，焦点从即将移除的原文链接交回重试按钮。初次选择文档的自动核验不主动转移焦点。

浏览器回归覆盖键盘 Enter 重试 PDF 后焦点进入原文链接、后台列表刷新不移走原文链接焦点，以及图片解码失败后焦点回到重试按钮；原有 409/404/503 与不伪造预览边界保持。全套浏览器测试首轮暴露另一条旧断言竞争：上传结束先启用文件输入，再等待列表刷新，最后才聚焦批次反馈。测试改为等待预期焦点或超时失败，仍检验可见轮廓；最终前端单测 13 项、8 个离线制品构建和 24 项 Chromium/Playwright 回归均通过。尚未做完整键盘遍历、真实屏幕阅读器或目标麒麟浏览器验收，FE-046 保持未完成。
