# P3 开放业务 API 与持久解析任务原型

日期：2026-09-23。环境：Mac、MinerU fork 4.0.6、隔离 SQLite/上传目录；Doclib 实测使用本机 Unix socket，非麒麟/NVIDIA。P1/P2 现场门槛和 P3 模板/复核/成果功能仍未完成。

## 需求修订

用户明确：系统开放使用，**没有用户和权限管理**。因此删除此前原型中的 `owner_id` 字段/过滤，不设计登录、角色、Skill 令牌；修订了架构、计划、执行规范及特性清单。任何能访问业务 API 的客户端都可读取和操作业务文档；生产部署必须靠物理隔离与内网可达范围控制风险。Doclib 内部 TCP 不对业务网络发布。人工复核和成果确认仍是内容状态规则，不是身份权限规则；操作记录不能伪称可定位个人。

## 已实现

- 单次上传先原子发布文件，再在一个 SQLite 事务中建立业务文档与初始任务；业务库登记失败时仅回滚刚上传且哈希未变化的文件。Doclib 提交失败保留业务文档、源文件和失败任务，可重试。
- 任务状态 `uploaded/submitted/done/failed`、请求/实际档位、parse ID、错误码持久保存；服务重建后可继续轮询。解析失败后重试使用 `force=True`；同一 parse ID 登记修订可安全重试。源文件哈希变化拒绝重试入库。
- `DoclibGateway` 合并待处理、新建和复用 parse ID。实测发现**已完成缓存命中也可能完全不返回 parse ID**；此时用公开 `list_parses` 按 SHA/tier 查询已完成记录，避免持久任务失去解析引用。若列表截断则拒绝装作成功。
- 依赖注入的 FastAPI 开放端点：`POST /api/business/documents`、`GET /api/business/documents/{id}`、`GET /api/business/tasks/{id}`、`POST /api/business/tasks/{id}/retry`。响应不泄漏宿主路径、存储键或 Doclib parse ID。接口没有登录或令牌检查，前端和自有 Skill 将共用此契约。

## 验证

`.venv/bin/python -m pytest tests/business -q`：**49 passed**；`ruff check mineru/business tests/business` 与格式检查通过。真实 Doclib 重复内容缓存用例通过：第二次 `ensure_parse` 返回 `done` 且空 ID 列表，公开列表补查后得到可追踪的已完成 parse ID。API TestClient 验证无认证请求可上传、查询、轮询完成和重试，响应不含内部文件路径；错误档位在写文件前被拒绝。测试产生的两条 Starlette/httpx/anyio 弃用警告来自当前依赖组合，非测试失败。

## 未完成与风险

- 尚无面向生产的业务 API 启动入口/镜像、限流与反向代理上传体积限制；当前 `UploadFile` 在应用层复制时限额，但入口代理仍需约束请求大小。API 可达网络范围及 Doclib 内部端口隔离尚未在 Compose/麒麟验证。
- SQLite 当前是开发期全新 schema，不做旧原型兼容；如果保存了本轮之前生成的临时开发库，需按“未上线、无数据迁移”前提重新初始化，不能把它当生产库原地升级。
- 上传文件与数据库无法做到跨资源原子事务；当前同步失败回滚仅覆盖“发布成功但登记失败”。进程在两步之间崩溃仍可留下孤儿文件，需安全的只读盘点与清理/恢复流程。
- 证据快照服务端真实性、并发重解析、模板/字段/质量问题、人工复核、成果、前端与自有 Skill 仍待开发；当前 API 只是解析任务链路，不是完整业务平台。
- 完全断网、模型驱动档位、真实样本质量与麒麟 NVIDIA 环境都未由这些 Mac 测试证明。
