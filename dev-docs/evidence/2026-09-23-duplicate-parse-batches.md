# Doclib 重复页批次与业务解析修复

状态：Mac 本地示例 PDF 回归通过；**未在麒麟/NVIDIA 上做真实模型与现场验收**。

此前全业务测试的示例 PDF 任务偶发 `parse_batch_invalid`。连续复跑并补充失败诊断后捕获到同一文档的三个已完成 Doclib 批次：两个页范围同为 `1-10`，一个为 `11-13`。业务库拒绝交叉重叠是正确行为；问题在于 Doclib 自动入库与显式 `all` 请求的竞争时序可能把相同范围重复排队。没有把失败简单改成成功，也没有取消业务库的重叠约束。

业务工作流现在只对**文档身份、档位和页集合完全相同**的已完成批次选取最新结果，记录所选 parse ID 到单个业务修订；部分重叠、缺页、身份或档位不一致仍被拒绝。原始任务保留全部 Doclib parse ID，便于诊断。集成测试失败时仅打印批次 ID、状态、页范围和档位，不输出原文或文件路径。

验证：新增精确重复批次与身份冲突单测，并将原先“相同范围重叠应失败”的测试调整为真正的部分交叉重叠；`tests/business/test_document_workflow.py` 10/10 通过。修复前真实示例 PDF 连续复跑出现重复 `1-10` 批次和失败；修复后同一集成测试连续 5 次通过。完整业务套件 `.venv/bin/python -m pytest tests/business -q --no-cov` 为 155/155，通过时有 2 个现有依赖弃用警告。该结果仅覆盖 Mac 本地 Doclib 与业务逻辑，不证明生产平台的模型、驱动或解析质量。
