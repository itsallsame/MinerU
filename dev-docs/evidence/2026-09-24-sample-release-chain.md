# 真实样本报告与离线发布记录的关联

日期：2026-09-24。范围：只读四类样本评估器的发布制品关联；尚无四类真实标注样本或麒麟目标机报告。

旧评估器只保留用户手填的 `--environment`。操作员即使拿错模型清单、镜像或过期运行态报告，也可能得到一份看似属于该部署的准确率报告。现在目标验收输入必须成组提供 `--release`、`--artifact-report`、`--runtime-report`；评估器复用运行态预检的制品报告核验，检查发布平台/源码提交/镜像 ID/模型清单、逐项制品计数，以及运行态报告对该制品报告的 SHA-256 关联。输出只写三份记录的哈希与必要的发布身份，不写模型权重或业务原文。任一文件缺失、符号链接、链条不符或参数不全时不生成总报告。

Mac 开发期没有离线发布记录时，须显式 `--allow-unbound` 且三份文件全省略；报告 `release_binding: null`，不能作为生产发布验收。三件套与 `--allow-unbound` 互斥。既有直接脚本命令和 `python -m` 命令均验证可启动。

定向 `tests/business/test_sample_evaluation.py` 为 12 passed，覆盖正确链条、运行态摘要错配、发布清单改动、参数缺项与显式未绑定开发模式；直接脚本与 `python -m` 两种入口均能启动。完整 `tests/business` 为 351 passed、2 skipped、2 个第三方依赖警告；Ruff lint、特性清单 JSON 与差异检查通过。

这只是**所给文件内部一致性**，不是签名，也不能证明业务 API 此刻仍运行这些镜像，或证明物理断网。目标机应在同一受控维护/验收窗口新跑制品与运行态检查，保持部署不变，再执行真实样本评估并共同归档报告。当前仅有 Mac 合成文件和 FastAPI 合成样本测试；P6 保持未完成。
