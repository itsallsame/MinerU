# 批量上传结果未知时的反馈边界（2026-09-24）

范围：开放业务 Web 的批量上传。没有引入用户、登录或权限管理，也没有自动重传不确定结果的文件。

- 修改前：上传请求断线，或服务返回 HTTP 202 但 JSON 响应损坏，界面显示普通错误；操作者可能误以为服务明确拒绝并再次上传。新增 Chromium 回归先证明了该问题。
- 修改后：上述两类情况标为“上传结果未确认”，提示可能已受理、先刷新文档列表核对、勿直接重复上传。明确的 HTTP 非成功响应仍按失败显示。
- HTTP 成功而任务状态字段缺失时，原先读取状态会抛错并显示失败；现在按“已受理，但任务状态未返回”提示，仍刷新文档列表。该边界也由新增回归先证明再修复。
- 浏览器测试确认三份文件各只发出一次 POST；不会因响应未知自动重传。批次结束后文件选择会清空，避免误触再次提交。
- 验证：`cd business-web && pnpm test && pnpm build` 均通过；完整离线 Chromium 套件 21/21 通过，其中包含新增的传输断线、损坏 JSON 和任务状态缺失用例。

边界：网络中断后，客户端无法单凭本次 HTTP 结果判断服务是否受理。当前提示要求人工核对，尚无服务端幂等键；这不是端到端恰好一次上传保证。真实麒麟目标环境和业务样本仍待验收。
