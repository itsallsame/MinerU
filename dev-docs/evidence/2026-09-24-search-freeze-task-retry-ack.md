# 检索冻结与任务重试的写入确认（2026-09-24）

## 风险与修复

- 检索结果“冻结此块原文”先创建不可变证据，再打开文档修订。原流程把两步放在同一个异常处理中；若证据已创建而后续修订读取失败，页面可能不说明证据已经冻结，甚至把打开文档的异常误标成“证据冻结失败”。现在 POST 失败才显示冻结失败；POST 成功后导航/修订读取失败明确显示“原文已冻结，但…”，并保持冻结按钮不可重复点击。导航已经切换到其他文档时仍只说明证据留在原修订，不抢回页面。
- 失败或待提交任务的“重新提交/提交”先 POST，再刷新文档列表。原流程在 POST 成功但列表 GET 失败后只显示连接错误。现在列表不可用时全局错误包含“任务已重新提交/已提交”，并保留既有的重新连接只读恢复入口；不会把服务已受理的任务说成提交失败。
- 开放系统约束不变：没有用户、登录或权限管理。

## 验证

- `business-web/tests/search_write_race_browser.py` 模拟证据 POST 成功、目标文档修订 GET 503，检查“已冻结”提示、冻结按钮不再可点及写入次数；保留旧的延迟导航竞争用例。新断言在修复前超时，修复后通过。
- `business-web/tests/upload_retry_race_browser.py` 模拟任务重试成功、文档列表 GET 503，然后重新连接；检查成功确认、任务状态恢复与重试 POST 次数不增加。
