# 人工复核写入的请求键恢复

日期：2026-09-25。范围：字段决定、质量问题处理、成果确认；同一开放业务 API 被业务 Web 调用，不引入用户、角色或权限层。

此前三类 POST 的响应丢失后，Web 只能查询当前复核状态，无法把状态变化归因于原请求；重复字段决定会留下重复审计，且新的决定 ID 可能影响之后成果快照。业务 SQLite schema 18 新增 `review_requests`。可选 `Idempotency-Key` 与动作、目标、规范化写入内容 SHA-256、原结果 ID 同事务提交；同键同意图返回原决定/解决记录/成果版本，不追加审计或新版本；同键异意图 409。`GET /api/business/review-requests/{key}` 只读返回动作、目标及原结果，404 只代表查询当时未记录。Key 是写入意图标识，不是身份或权限。

Web 在 POST 前将请求键、目标和原写入内容保存到同源本地存储；存储不可写则拒绝发送。未知 POST 响应只按原键 GET；查不到或暂时不可读时保留键，刷新后仍提供只读核对。用户明确确认后才可用**同键同内容**重试；同一提取运行有未确认写入时暂停新的复核写入。已受理后若后续列表读取失败，仍报告写入已受理并允许只读重试。浏览器存储可能暴露给同源脚本，部署必须保持业务 Web 的隔离网络边界并控制同源代码；本方案不声称本地存储是保密或防篡改机制。

Mac 验证：存储并发同键决定只形成一条审计；三类同键重放、异意图冲突、确认后原版本找回；API 请求键查回、404/422；备份缺少新表拒绝。完整 `tests/business` 为 398 通过、2 跳过、2 个依赖警告。Web 单元测试 13 通过、8 个离线资产构建成功、29 个 Chromium 浏览器回归通过；新增回归覆盖响应丢失、只读核对失败、刷新恢复、404、人工确认同键回放及浏览器存储不可写。Ruff 和 diff 检查通过。

后续补强：确认 API 已增加决定/问题快照前提，避免旧页面静默确认另一页面的新复核状态；详见 `2026-09-25-review-snapshot-precondition.md`。证据冻结 POST 及其他未列出的写入不由本请求键覆盖。schema 17 不迁移或自动删除；需保留时先归档，并用新空库启动 schema 18。真实网络故障、已标注业务样本和隔离麒麟 x86_64＋NVIDIA 目标机均未验收。
