# Doclib 队列释放：逐批次事实而非统一停算承诺

日期：2026-09-24。基线：fork `master` 的 `bbb9403c`。实现范围仅 Doclib v4 及业务端对意外 `skipped` 的失败识别，不包含业务取消流程或前端/Skill 入口。

Doclib 现在记录稳定消费者意图的持久墓碑和首次释放结果 JSON 快照；释放与 worker 领取、新请求登记在同一个 SQLite 写锁下裁决。独占且仍在队列、仅有一条非 watch 活跃文件路径的批次可标记 `skipped`。共享引用、正在解析、已结束、存在 watch/多路径等情况不会被冒充为停算。重复释放复用持久化的逐批次结果；即使解析批次及其引用后来被清理，重启后的 Doclib 仍返回首次结果。先释放后提交同一键被拒绝。后台重复发现同 SHA 时为活跃批次补系统引用；若先前独占批次已跳过，之后的后台发现会重新排一个受保护批次，避免把后来的系统需求吞掉。

本地验证覆盖独占、两业务意图共享、多页多批次、后台重复内容、运行中、已完成、watch 保守保留、先释放后提交、跳过后后台新发现、释放与 worker 领取并发、迁移及真实 SDK/Unix-socket 路由。完整官方单元测试为 2827 passed / 4 skipped；完整 Mac 业务测试为 249 passed / 1 skipped；最终 Doclib/迁移/接口/真实 SDK 与业务工作流子集为 79 passed。最后增补的匿名 SDK 保护引用测试单项通过；集成子集在本机沙箱内首次重跑因 Unix/TCP 绑定权限失败，按本地测试许可重跑通过。测试未声称模型运行中可抢占，也未覆盖跨业务库/Doclib 崩溃恢复或隔离麒麟/NVIDIA 实机。

安全边界：这里没有用户、登录、角色或权限体系；消费者键只用于幂等和批次引用，不是秘密。Doclib 的低层释放接口应保持在部署规划的内部网络/UDS 边界内，不能被前端或 Skill 绕过业务 API 直接使用。业务任务取消仍需先持久化意图并处理跨库未知结果，故 FE-016 保持未完成。
