# 运行态挂载清单白名单

日期：2026-09-24。分支：`master`。环境：macOS 模拟 Docker inspect 数据；未在麒麟 x86_64/NVIDIA 上启动 Compose。

发现：上一轮宿主路径隔离检查只核对约定挂载。若额外将模型宿主目录绑定到业务容器的不同目的路径（例如 `/different-name`），原检查既不会看到业务容器的模型目录，也不会将其纳入路径重叠比较，运行预检可误报通过。

修复：`verify_business_runtime` 先要求实际 `Mounts` 目的路径与设计清单完全一致：业务容器仅业务数据和共享原件，worker 仅 Doclib 数据、共享原件、只读模型及只读模型清单。缺失、重复或额外挂载均失败，随后继续检查每个挂载的 bind 类型、读写模式、宿主源路径与相互隔离。此检查不会修改容器或文件。

验证：定向运行态与宿主布局测试 39 项通过，包含模型目录以其他名称挂入业务容器、worker 多挂载、缺失挂载和缺失清单；完整业务测试 171 项通过、2 个已有依赖弃用警告，运行时仅授权本机测试 socket。Ruff 检查/格式检查及 `git diff --check` 通过。真实 Docker inspect 的 Mounts 内容与目标机隔离状态仍须现场验证；不能从模拟数据推断已实现物理隔离。回滚仅撤销预检和文档，不影响数据。
