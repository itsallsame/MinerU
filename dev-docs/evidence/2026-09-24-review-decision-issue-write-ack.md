# 复核决定与问题处理写入确认（2026-09-24）

## 问题

候选接受、人工修订、问题标记已解决、有依据地忽略，均先 POST 写入，再通过 `loadRun` 重读运行详情、模板、决定、成果和审计。若 POST 已返回 201，后续任一 GET 返回 503，旧页面只显示“复核数据读取失败”，没有说明刚才的决定或处理已保存，容易造成重复操作与审计噪声。

## 实现

新增复核写入后的统一只读刷新辅助流程。成功收到 POST 响应后，后续读失败时保留“复核决定已保存”或“问题处理已保存”的明确确认，并继续显示“重试读取提取运行”。重试只执行 GET，不重发 POST。成果版本确认也复用这一流程，保持上一轮的版本号确认语义。写入本身失败时不显示成功确认。

不增加用户、登录或权限管理；开放系统约束不变。

## 验证

- 新增 `business-web/tests/review_write_refresh_browser.py`，逐项模拟四条写入路径的 POST 201、后续决策或审计 GET 503，然后恢复 GET；逐项断言相应 POST 次数不因读取重试增加。
- 新浏览器回归在修复前于第一个“已保存”断言失败；修复后完整通过。
- `cd business-web && pnpm test && pnpm build && pnpm test:browser`：11 项 Node 测试通过，离线构建成功，20 项 Chromium 浏览器回归通过。

这是 Mac 上的合成 API 验证，不证明真实文档样本或麒麟 x86_64/NVIDIA 离线目标机验收。FE-047 的全局异步错误恢复仍有其他路径待审计，因此保持未完成。
