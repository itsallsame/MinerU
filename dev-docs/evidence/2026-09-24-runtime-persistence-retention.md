# 运行态持久化路径与历史批次保留检查（2026-09-24）

## 风险

业务证据绑定历史解析批次。Compose 设置 `MINERU_DOCLIB_COMPACTION_INTERVAL_SEC=0`，但旧运行态预检只核对模型离线配置、挂载、网络及 GPU；若实际 worker 容器重新启用 Doclib 默认压缩，仍可能取得成功报告。类似地，挂载虽正确，业务数据库或上传目录的环境变量却可能改指容器临时路径，导致数据不持久或跨容器原文件不一致。

## 改动

- worker 运行态必须把 `MINERU_HOME`、模型目录、模型清单指向已校验挂载，并禁用 Doclib 历史批次压缩。
- business API 运行态必须把 SQLite、共享上传、Web 静态目录指向约定位置，并要求 Web 资源存在。
- Compose 静态回归核对这些变量与运行态契约一致；运行态负例覆盖压缩重新启用、模型/Doclib 路径漂移、业务 SQLite/上传/Web 路径漂移。
- 开放系统约束不变，没有增加用户、登录或权限管理。

## 验证与边界

- 五项新运行态负例在修复前未被拒绝；修复后加入更多模型清单与 Web 路径负例，共 39 项运行态专项测试通过。
- Compose/运行态专项合计 51 通过、1 跳过（受限环境未访问 Docker）；完整业务测试在 Docker 可访问环境中 210 通过、1 跳过，Ruff 通过。
- 这是 Mac 上模拟容器 inspect 的预检逻辑验证。尚未在物理隔离麒麟 x86_64/NVIDIA 机器上启动并检查真实容器；也未验证长期批次保留、容量增长或真实样本质量。P1/P6 保持未完成。
