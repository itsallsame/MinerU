# 字段提取写入确认与读取恢复（2026-09-24）

## 问题与边界

复核页发起“重新生成字段候选”时，`POST /revisions/{id}/extractions` 可能已经返回 201，但紧接着读取提取运行列表或证据列表失败。旧实现把整个流程当作一次失败，页面继续提供生成按钮，用户可能误以为没有提交并重复创建运行。

## 改动

- 收到成功写入响应后立即记录新运行 ID、目标运行 ID 和本地运行列表；读取列表短暂滞后时保留这个已确认运行。
- 后续列表/证据读取失败时明确显示“字段提取已提交”，进入解析修订读取重试状态；重试只读，不重发 POST。
- 新运行详情读取失败时同样保留写入已确认的说明，并提供既有的“重试读取提取运行”。
- 仍是开放系统；未增加用户、登录或权限管理。

## 验证

- `business-web/tests/review_recovery_browser.py` 在本地拦截 API：POST 返回 201，随后的运行列表 GET 返回 503。修复前浏览器断言失败；修复后显示已提交提示，恢复读取后只观察到一次 POST。
- `cd business-web && pnpm test && pnpm build`：11 个 Node 测试通过，离线 Web 构建成功。
- `cd business-web && pnpm test:browser`：19 个离线 Chromium 回归通过。

这是 Mac 上的合成 API 浏览器验证，不代表真实样本验收或麒麟/NVIDIA 目标机验证。FE-047 仍未完成全部异步路径审计。
