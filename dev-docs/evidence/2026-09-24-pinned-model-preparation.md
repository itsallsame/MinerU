# 离线模型精确版本准备（Mac 模拟验证）

范围：只补联网准备机的模型获取流程。系统仍是开放业务 Web/API 和自有 Skill，共用业务接口；不建立登录、用户、角色或权限管理。生产机完全断网，模型权重单独放在麒麟宿主只读目录，不进入 Git 或代码镜像。

实现：`scripts/prepare_offline_models.py` 要求 Torch 小模型仓库与 vLLM 仓库各给出精确的 40 位 Hugging Face 提交 SHA；逐仓库核对解析后的提交和远端文件列表，下载到新暂存目录，拒绝缺少必需路径、下载文件集合不符和符号链接。成功时写入两个仓库的来源锁、MinerU 完整标记和目录外 SHA-256 清单；旧模型目录与旧清单不得覆盖。部署命令和版本选择见 `dev-docs/offline-deployment.md` 第 2 步。

验证：`tests/business/test_prepare_offline_models.py` 只用模拟 Hugging Face API/下载器，覆盖精确提交、浮动版本拒绝、远端 SHA 不符、必需文件缺失、下载额外文件、已有制品不覆盖及符号链接输出父目录拒绝。目标测试 23 通过、1 跳过（含既有离线配置测试）；完整业务回归 290 通过、1 跳过、2 条既有依赖警告；Ruff lint 与格式检查、`git diff --check` 通过。首次沙箱内运行的真实 Doclib 联调因本地 Unix/TCP 套接字绑定被拒而失败，获得本机回环权限后的完整重跑全部通过。

限制：没有在 Mac 下载真实权重，也没有 Linux amd64 联网准备机、隔离麒麟主机、NVIDIA/vLLM 组合或真实复杂文档样本的验证。来源锁和本地哈希不替代独立可信渠道的版本审批、介质交接、模型加载和解析质量验收。磁盘空间不足时不应在 Mac 上尝试真实权重下载。失败下载的暂存目录被保留供检查，不作为可发布制品。
