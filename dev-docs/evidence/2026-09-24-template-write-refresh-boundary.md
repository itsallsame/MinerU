# 模板写入与列表刷新故障边界（Mac，2026-09-24）

## 问题

模板创建、升版或停用的写入请求成功后，Web 会再次 GET 模板列表。此前这两个动作共用一个 `try/catch`：若 GET 失败，界面会将已成功写入的操作报为失败，保留旧列表和编辑态，可能诱导用户重复提交，导致重复创建冲突或额外版本。

## 行为修正

- 写入响应是该次操作是否成功的依据；先将响应中的模板版本合入本地列表，同步上传模板选择和当前详情。
- 后续完整列表刷新失败时，以成功状态说明“已保存/已停用”，附带独立刷新警告和稍后核对提示，不把已成功写入改判为失败。
- 原有延迟写入后切换模板的选中态隔离保持不变；系统仍无用户、登录或权限管理。

## 验证

扩展 `template_browser.py`：创建和停用均模拟写入成功、随后 GET `/templates` 返回 503；断言成功确认、没有错误警报、写入响应驱动的列表和上传选择更新，写入次数仍为创建、升版、停用各一次。`template_write_race_browser.py` 继续验证延迟写入不覆盖较新的选择。

Mac 验证：`pnpm test` 11/11，`pnpm build` 8 个离线资产，`pnpm test:browser` 19/19。上轮证据重试浏览器测试还改为等待实际 503 响应，避免测试自身与 DOM 更新竞争。以上不替代真实文档或麒麟/NVIDIA 离线验收；FE-047 其他异步路径仍需审查。
