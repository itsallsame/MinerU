# P3 开放复核与不可变成果（2026-09-23）

## 状态与数据契约

- `field_decisions` 追加记录字段旧值、新值、证据、候选接受/人工修正、操作来源、原因和时间。候选不经显式决定不能进入成果。人工修正需原因，证据必须来自同一解析修订；即使新值是规范化表达，仍能展示原文片段及“人工修正”标记。
- `quality_issues` 的阻断问题由 `issue_resolutions` 留痕。必填缺失不能忽略；解决缺失/冲突需先有字段决定。解析覆盖不完整不能解决或忽略，必须换完整来源/解析运行。
- `confirmed_results` 保存按运行递增的不可变结果版本、字段/证据/决定 ID 快照和哈希。结果只收录显式决定的字段；已有版本不随候选、问题或后续人工决定改变。相同决定快照不可重复确认。
- `audit_events` 在字段决定、问题解决、成果确认的同一数据库事务内追加。操作来源只表示 `web`、`skill` 或 `api`，**不代表个人身份**；系统没有用户、登录、角色或权限管理。
- 开放业务 API 提供字段决定、问题解决、确认、结果版本读取与审计读取；前端/Skill 后续共用这些契约。Skill 默认不得自动确认是 Skill 行为规则，不是 API 权限。
- SQLite 原型 schema 5；旧 schema 不迁移也不自动删除，使用新空库进行本轮原型测试。

## 验证

- 覆盖候选不得自动确认、必填决定、冲突与缺失阻断、覆盖不完整不可豁免、跨修订证据拒绝、人工修正必须说明原因、旧成果版本冻结、重启持久性、操作审计和开放 API。
- Mac 完整 `tests/business`：**80 passed、2 warnings**（58.11 秒，本地 socket 已允许）；Ruff 检查通过。
